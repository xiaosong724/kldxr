## 1. 为什么先做组队

```
① 标题里就有"组队"✗ 现在完全没有 ✓ 三个人在同一张地图上，但彼此只是"会动的路人"✗
② 末日题材的核心体验是【互相扶一把】✓
   现在队友倒下了你只能看着（连他是死是活都只能靠猜 ✗）
③ 它能把已有的一堆东西串起来：
   队友方位箭头 ✓ 复活机制 ✓ 掉落 ✓ 聊天 ✓ —— 现在都是各干各的 ✓
④ 技术风险低 ✓：纯内存状态 + 复用现有协议 ✓ 不需要动数据库 ✗
```

## 2. 一句话定义

> **最多 4 人结成一队：共享经验、互相看得见状态、能互相救起来。**

不做的东西（明确划出去，免得越做越大 ✗）：

```
✗ PvP / 友伤        —— 本作是合作 PvE ✓ 没有友伤 ✓ 范围技能也不会打到队友 ✓
✗ 抢掉落            —— 掉落保持【个人掉落】✓ 谁的击杀谁掉 ✓ 不共享不改归属 ✓
✗ 强制职业分工      —— 不规定"你是坦克他是奶"✗ 分工靠武器和技能自然形成 ✓
✗ 队伍仓库 / 共享背包 —— 不做 ✗（要防"队里有人卷走东西"这类问题 ✓ 干脆不做 ✓）
✗ 跨服 / 持久化队伍  —— 队伍是【临时的】✓ 服务器重启就解散 ✓
```

## 3. 玩法规则

### 3.1 基本

| 项 | 规则 |
|---|---|
| 队伍上限 | **3 人**（含队长）★ 用户已确认 |
| 创建 | 邀请制 ✓ 第一个发起邀请并成功的人自动成为队长 ✓ |
| 加入 | 附近玩家列表里点【邀请】→ 对方收到弹窗 → 接受即入队 ✓ |
| 邀请条件 | 目标在 **20 米**内 ✓（防全图骚扰 ✗）· 每人 10 秒最多发 3 次邀请 ✓ |
| 退出 | 主动退队 ✓ · 被队长踢 ✓（队长不能踢自己 ✗ 要踢先转让或解散 ✓）|
| 队长 | 可踢人 / 可解散 / 可转让 ✓（队员也能邀请人 ✓ 但上限受队长控制 ✓）|
| 解散 | 队长解散 · 或队里只剩 1 人时自动解散 ✓ |
| 掉线 | 视为退队 ✓（重连不自动回队 ✓ 需要重新邀请 ✓）|

### 3.2 经验共享

```
★ 用户已确认的方案（比原来的"队伍加成"更稳 ✓）：
   自己杀的僵尸 → 自己拿【100%】✓
   队友杀的僵尸 → 每个队友拿【该僵尸经验的 10%】✓
                   和队伍人数无关 ✓ 不会因为人多而通胀 ✓

★ 为什么这个设计好：
   · 总量可控：3 人队最多多出 20% 的总经验产出 ✓（原来那版 4 人是 5.2 倍 ✗）
   · 动力还在：一起打，虽然不如自己杀得多，但比自己单飞去别处打要强 ✓
   · 不会出现"组队练级反而变慢"✗（因为自己杀的那份一分不少 ✓）
★ 30 米内才算 ✓（防"人在别的区挂机蹭经验"✗）
★ 距离用【击杀时】的位置判定 ✓ 不是全程跟踪 ✓（简单够用 ✓）
```

```
① 队伍面板（屏幕侧边常驻 ✓）
   每人一行：名字 · 等级 · 血条 · 灵气条 · 手上武器图标 · 队长标记 ✓
   自己那行高亮 ✓
   有人倒下 → 那一行变红 + 显示【倒地 12 秒】倒计时 ✓

② 世界里的标识
   · 队友名字用队伍色（不用再和路人一个颜色 ✓）
   · 队友头顶多一条【细血条】（不用点开面板就知道他快死了 ✓）
   · 已有的"队友方位箭头"改成【只对队友生效】✓ 路人不再显示 ✓（现在是 50 米内所有人都显示 ✗）
   · 队友倒地 → 屏幕边缘一个红色箭头 + "XX 倒下了" ✓（这条最重要 ✓
     现在队友死了你根本不知道 ✗）

③ 队伍频道聊天
   聊天框多一个【队伍】频道 ✓ 只有队里人看得到 ✓
   默认频道：没队伍时是世界 ✓ 有队伍时是队伍 ✓ 可以手动切 ✓
```

## 4. 技术方案

### 4.1 状态放哪（沿用现有铁律 ✓）

```
★ 全部状态放【tick 线程】的 World 里 ✓ 纯内存 ✓ 不加锁 ✓ 不碰磁盘 ✓
   （和当年定的一样：世界只有一个线程能改 ✓）

World 里加两张表：
   self.parties   = { party_id: {'id', 'leader': cid, 'members': [cid...], 'ts'} }
   self.party_of  = { cid: party_id }        # 反查：这个人在哪个队
   self.party_inv = { cid: [(from_cid, ts)...] }   # 待处理的邀请（带过期 ✓）

★ 不加数据库表 ✓ 不进存档 ✓ 服务器重启 = 队伍解散 ✓
  理由：队伍是"此刻在一起的人"✗ 不是资产 ✓ 持久化只会带来"僵尸队伍"这种麻烦 ✓
```

### 4.2 协议

```
客户端 → 服务器：一个消息走所有操作（少加类型 ✓ 好维护 ✓）
  { t: 'party', d: { op: 'invite'|'accept'|'decline'|'leave'|'kick'|'promote'|'disband'|'chat',
                     cid?: 目标, text?: 聊天内容 } }

服务器 → 客户端：
  { t: 'party', d: { roster: [...] | null, pid, leader, myCid } }   # 队伍变化时全量推一份
  { t: 'partyinv', d: { from: 名字, pid } }                        # 收到邀请（弹窗 ✓）
  { t: 'partychat', d: { from: 名字, text } }                      # 队伍频道
  { t: 'partydown', d: { cid, name, x, z, left: 12.0 } }           # 有人倒下了（箭头/提示 ✓）

roster 里每人的字段（只推必要的 ✓ 30 秒推一次 or 变化时推 ✓）：
  [cid, 名字, 等级, hp, hpMax, qi, qiMax, 武器 look, 是否倒地, 是否队长]

★ roster 刷新频率：变化时立刻推 ✓ 另外每 1 秒补推一次（血条要动 ✓）
   —— 4 个人的 8 个数字 ✓ 一秒钟一次可以忽略不计 ✓
```

### 4.3 经验共享改哪

```
位置：world._mob_died()（击杀结算的地方 ✓）
现在：只给击杀者算经验 ✓
改成：
   base = mob_exp(m.lv)
   bonus = PARTY_EXP_BONUS[len(members)]        # [1.0, 1.1, 1.2, 1.3]
   for 每个队员 q：
       if 距离(m, q) > 30: 跳过 ✓
       exp = int(base * bonus)
       给 q 加经验（复用现有的经验/升级逻辑 ✓）
       给 q 发一个飘字/提示（复用现有的 me 通道 ✓）
★ 击杀者【也在队里】的话走同一条路 ✓ 不额外多给 ✗（不然自己单刷组队反而更亏 ✓）
```

### 4.4 队友救援改哪

```
服务器侧：
  · 新增一个"救援中"的状态：{ helper_cid, target_cid, left, x, z }
  · 救援意图（复用 revive 消息，加一个 target ✓）
  · 每 tick 检查：helper 还活着吗 ✓ 还在 2 米内吗 ✓ 挨打了吗（挨打就打断 ✓）
  · 完成 → target 起来：hp = 50% + 1.5 秒无敌 ✓（复用现有的复活逻辑 ✓）
  · 目标必须是"倒地状态"✓ 且不能救自己 ✓
倒下计时：
  · 玩家 hp<=0 时记 downSince ✓ 每 tick 检查 12 秒 ✓
  · 超时 → 回堡垒复活点 ✓ 满血 ✓（需要新增"复活点"坐标 ✓ 用现有的安全区坐标 ✓）
```

### 4.5 客户端改哪

```
① 队伍面板（新面板 ✓ 挂到现有的 UI 面板体系里 ✓）
② 附近玩家列表 + 邀请按钮（复用现有的玩家列表数据 ✓）
③ 邀请弹窗（接受/拒绝 ✓ 10 秒过期 ✓）
④ 队友头顶细血条（复用现有的"头顶 UI"机制 ✓ 那套已经给僵尸用了 ✓）
⑤ 队友方位箭头（现在就有 ✓ 改成只对队友 ✓ + 倒地变红 ✓）
⑥ 聊天频道切换（现有聊天框加一个切换 ✓）
⑦ 救人按钮（靠近倒地的队友时出现 ✓ 按住 2.5 秒 ✓ 有进度条 ✓）
★ 所有 UI 都走现有平台层 ✓ core 里不碰 DOM ✗（分层铁律 ✓）
```
