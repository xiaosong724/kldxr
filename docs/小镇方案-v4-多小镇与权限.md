## 1. 权限系统

### 1.1 权限项

最终保留 **7 项**：

| key | 名称 | 作用 |
|---|---|---|
| `move` | 可移动 | 移动已放置物、切换地面材质、放置新物件（是否合并待确认） |
| `interact` | 可交互 | 坐椅子、开门、使用床/冰箱/设施 |
| `trade` | 可交易 | 购买、点单、租房 |
| `perm` | 可权限 | 给其他玩家授予/撤销权限（不能超过自己拥有的权限） |
| `remove` | 可移除 | 从管理界面收回/删除放置物 |
| `price` | 可调价格 | 调整自己小镇内商店/服务的价格 |
| `teleport` | 可传送 | 使用小镇传送阵进出 |

> 原先的“可破坏”与“可移除”重复，已合并；地面只换材质，不挖坑。

### 1.2 权限主体

- 小镇主人：默认拥有全部 7 项，不能被普通权限人移除；
- 系统管理员：全局拥有全部权限，可越过任何小镇限制；
- 访客：默认 `interact + trade + teleport`；
- 授权玩家：按玩家单独设置 7 项开关；
- 权限人只能授予/撤销自己拥有的权限（`perm` 不能提权）；
- 管理员可以修改任意玩家的权限，也可以改“访客默认权限”模板。

### 1.3 权限存储

- 数据库按 `(town_id, player_id)` 存一份 7 位掩码/JSON；
- 内存中按小镇缓存，修改后广播；
- 服务端所有操作必须校验权限；客户端只负责显示按钮。

## 2. 小镇数据

### 2.1 小镇状态

- `active`：正常存在；
- `frozen`：到期冻结，世界不加载，数据保留 7 天；
- `deleted`：7 天后永久删除；
- `restoring`：恢复中，等待选坐标。

### 2.2 小镇字段

```text
towns
  id
  owner_id
  name
  tier           30/50/80/100
  size_grid
  origin_x, origin_z        # 左下角/中心，最终定一种
  status
  created_at
  expires_at
  last_fee_at
  auto_pay
  original_origin_x/z       # 冻结时原坐标
  is_system       # 系统主城
```

### 2.3 世界与加载

- 世界是动态的，不再限制 500×500；
- 客户端按区块加载地形/物件；
- 服务端只对“有玩家的附近小镇”做 tick/加载；
- 玩家离开后小镇不渲染、不模拟；
- 小镇之间按 50 格间距做 AABB 占位检查；
- 创建小镇时坐标不能压主城、不能压其它小镇、不能超过世界安全范围。

### 2.4 创建流程

1. 打开地图/建镇面板；
2. 选尺寸 30/50/80/100；
3. 在可放置区域选坐标，实时显示 50 格间距与占用；
4. 支付首日维护费；
5. 创建小镇，写入默认权限；
6. 小镇立即成为安全区（边界 +2 格）；
7. 主人获得全部权限。

### 2.5 到期、冻结、恢复

- 每日固定时间扣费；自动模式余额不足 → 立即冻结；
- 冻结时从世界移除所有对象/传送点，但保留数据；
- 保留 7 天，7 天后永久删除；
- 恢复：
  - 支付恢复当日费用；
  - 原坐标仍空 → 可原地恢复；
  - 原坐标被占 → 必须重新选坐标；
  - 尺寸、对象、权限、收益记录全部保留。

### 3.1.1 目录字段

管理员后台维护 `town_catalog`：

```text
catalog_id
name
category       building/shop/teleport/seat/decor/ground
size_grid_w/d

collision_boxes  # 多个局部 AABB，支持门洞/内部家具

```

- 现有 10 家商店、传送阵、住宅、椅子、装饰全部目录化；
- 主城也由这些对象记录组成，不再是写死的静态布局；
- 纯装饰品 `function_type=none`。

### 3.2 放置

- 仅主人/有 `move` 权限的人可放置；
- 模式：
  - 格子吸附：0.62m 对齐；
  - 自由位置：任意坐标；
- 旋转：
  - 90°；
  - 任意角度（碰撞用 OBB）；
- 放置前显示碰撞盒预览；
- 与已有物件/小镇边界重叠时禁止；
- 放置扣目录价格；
- 放置后归小镇主人所有；
- 移除不退款（待确认）。

### 3.3 碰撞

- 每个目录物件提供**多个局部碰撞盒**，不是整体一个 AABB；
- 建筑保留门洞和内部可走区域；
- 家具、椅子、柜台、花盆都有碰撞；
- 客户端移动碰撞 + 服务端校验使用同一份碰撞数据；
- 自由角度用 OBB/SAT 检测。

### 3.4 地面材质

- 地面是 0.62m 方块网格；
- `town_ground` 稀疏保存每格材质覆盖；
- 只能替换材质，不能挖空/改变高度；
- 地面不产生滑/减速等特殊效果；
- 修改地面材质的权限/费用待确认。

### 3.5 功能物件

放置后功能必须真的存在：

- 超市/商店：货架、交易、点单；
- 传送阵：加入小镇传送网络，按 `teleport` 权限使用；
- 椅子：可坐；
- 住宅：可购买/租用/睡觉/冰箱；
- 装饰：无功能。

## 4. 经济系统

### 4.1 收入

小镇收益来源：

- 商店购买；
- 餐饮点单；
- 传送费（如果有）；
- 房屋租金/买断。

每笔交易：

```text
owner_gain = floor(amount × 80%)
tax        = amount - owner_gain
```

- 80% 进小镇主人账户；
- 20% 进系统税账户；
- 主人离线时进待入账账本，登录补发；
- 后台可查税收流水。

### 4.2 支出

- 创建费/每日维护费 → 系统；
- 放置物件费用 → 系统；
- 恢复费 → 系统。

### 4.3 价格

- 物件目录价格由管理员后台设置；
- 商店商品价格由有 `price` 权限的人调整；
- 调整范围、基准价和管理员上限待确认。

## 11. B 阶段落地（2026-10-22）

### 已确认的规则

- **20% 系统税 = 直接扣掉**（用户原话："就是相当于扣掉了"）：不入任何账户，
  `town_ledger` 只记 `owner_gain` / `tax` 两栏。
- 建镇首日、恢复当日费用都按**当天 00:00 到期**算（`towns.next_due_ms`）。
- 每日维护费取整到万，本地 00:00 结算。

### 已完成

- **B1 每日扣费 + 冻结**（`world._town_fee_tick`，每 5 秒检查一次）：
  - 到期时在线玩家走内存金币，离线玩家走 `towns.charge_offline` 的原子 UPDATE；
  - 余额够 → 续到下一个本地 00:00，写 `town_payments(paid)`；
  - 余额不够 / `auto_pay=0` → 立即冻结，保留 7 天，写 `town_payments(failed)`；
  - 建镇/恢复改成"到当天 00:00"，并各写一条 `town_payments`。
- **B2 80/20 分账**（`world._town_revenue`）：
  - 商店购买、坐下点单都会立刻分账；
  - 玩家小镇：主人 80%，20% 直接扣掉；主人离线进 `pending_gold`，登录补发；

### C3 对照实验（2026-10-22）：对象镇平移到旧主城

不动数据库，只在客户端加预览开关：`/?townobj=1&tox=-130&toz=130`
（隐藏静态建筑/房子/道具/椅子，把 309 个放置物按 (-130,+130) 平移到旧镇路面上）。

- `docs/shots/town-switch-old.png` —— 现状（旧静态镇）
- `docs/shots/town-switch-new.png` —— 对象镇平移后的样子
- 工具：`tools/preview_town_switch.py`

**结论：方向可行，但现在不能切。**

1. **对齐**：23 栋里有 21 栋的坐标差正好是 (-130, +130)，平移到旧路面上基本严丝合缝；
   例外是超市（偏 20m，因为新模型体量不同重新摆过）和咖啡店（偏 2m）。
2. **观感**：新模型细节明显好于旧盒子，广场/路面沿用旧的很自然；
   但静态道具（树/长椅/路灯/花坛）一藏，镇子边缘会变空。
3. **性能是硬门槛**：预览里 309 个放置物是 `place.js` 逐个建的完整模型（含内景家具），
   同机 FPS 从 37 掉到 19。正式切换前必须先把放置物做**合并/实例化 + 距离 LOD**，
   否则主城性能会明显回退。

**建议顺序**：先做放置物合批（同材质合并 + 远处简模），再切静态渲染器；
切换时保留旧的地面/道路/广场，只隐藏建筑/房子/椅子，道具按需保留。

> 预览开关默认关闭，不影响线上。
