# 改代码 → 上线的工作流程（★ 必须遵守）

> 起因：第 207 轮我在云端上线了自动战斗 ✗
>   用户原话："不是说让你在本地做完了我确认后再同步吗"

>   这是流程问题 ✗ 不是技术问题 ✓ 所以写成文件钉在这里 ✓

## 铁规矩（三步，不许跳）

```
第一步  本地做 + 本地测
          · 服务器跑在本地（127.0.0.1:8899）
          · 用 headless 浏览器真跑一遍（不是"看着像对"✓ 要看数据 ✓）
          · 截图/读数值留证据

第二步  ★ 停下来，向用户报告 + 等确认 ★
          · 报告：改了什么 / 本地测出来什么 / 可能影响什么
          · 明确问一句："可以同步到云端吗？"
          · ★ 用户没明确说"可以"，就【不许】碰云端 ✗✗

第三步  确认后才同步
          · 同步必须：先停服务 → 复制 → 再起服务
            （第 196 轮的教训：边跑边传，玩家会看到半个页面 ✓）
          · 同步后再从外网验一次 ✓
```

## 为什么这条对（不是形式主义）

```
· 云端现在是【朋友在玩的正式服】✗ 不是我的试验场 ✓
  我传一次 = 可能把正在玩的人踢下线 / 弄坏存档 / 造成维护页 ✓
· 已经出过两次事：
    第 196 轮：边跑边传 → 用户看到 "SETCFG is not defined" ✓
    第 207 轮：停服务重启 → TIME_WAIT 卡住 → 服务起不来 ✓
· 本地随便折腾 ✓ 云端要稳 ✓ 两件事必须分开 ✓
```

## 具体的"不许"

```
✗ 不许"顺手就传了"（哪怕是修 bug ✓ 也要先问 ✓）
✗ 不许在用户玩的时候停服务（除非用户说可以 ✓）
✗ 不许因为"本地测过了"就省略第二步 ✗ 本地测过只是【第二步的前提】✓
✗ 不许把"我以为他会同意"当成同意 ✓
```

## 本地测试的标准动作（第一步怎么做才算数）

```

2. headless 真客户端连 127.0.0.1 ✓ 走完整流程：
     登录 → 进世界 → 操作 → 读数值（不是只看页面有没有报错 ✓）
3. ★ 测试脚本自身也要检查一遍：
     最近三次"以为是功能坏了、其实是测试写错了"✓

```

## ★ 往 HTML 里插 CSS 的坑（第 248 轮又踩了一次）

**症状**：样式完全不生效（文字在 ✗ 但边框/底色/字号全没有）
**原因**：把新的 `<style>…</style>` 插到了【已有 `<style>` 的内部】
  → 那段 CSS 变成了上一条规则的文本 ✗ 浏览器当垃圾丢掉了 ✓
**正确做法**：
  · 插在 `</style>` 的【后面】✗ 或者直接追加到已有 `<style>` 的【末尾】
  · ★ 改完一定要数一下 `<style>` 和 `</style>` 是不是配对的
**同类历史**：第 68 轮"瞬移按钮看不见"也是这个原因（CSS 插进了 `#atk{…}` 规则内部）
**教训**：改 CSS 之后不要只看"代码在不在"✗ 要看"浏览器认不认"✓
  → 最快的验证：无头浏览器截图看一眼 ✓（本轮就是这么发现的 ✓）
