# 视角转动（自由转 + 一键锁定）· 方案（round497，未实装）

> 用户："再增加一个视角转动功能，加一个按钮，点击后开启，再点击锁定视角"

---

## 1. 一句话

右上角加一个 **「转视角」** 按钮：
- 点一下 → **开启**：手指拖动就能绕着角色转视角
- 再点一下 → **锁定**：视角停在你最后调到的角度，不弹回去
- **长按 1 秒** → 回正（回到游戏原来的默认角度）

---

## 2. 现在的相机是什么样（先看清再改）

`web/core/game.js` 第 7908 行，每帧算一次，**角度是写死的**：

```js
cam.position.set(P.x + sx,
                 _camY + 1.4 + G.CAM_DIST * Math.sin(G.CAM_PITCH),
                 P.z + G.CAM_DIST * Math.cos(G.CAM_PITCH) + sz);
cam.lookAt(P.x, _camY + 1.4, P.z);
```

- `G.CAM_PITCH = 1.02`（俯角）· `G.CAM_DIST = 21`（距离）
- 只有 `+Z` 一个方向的偏移 → **没有"绕"的概念** ✓ 所以现在转不了
- `sx / sz` 是砍击时的镜头抖动

**改法**：加一个 `G.CAM_YAW`（弧度，默认 0），把偏移向量绕角色转一下：

```js
var _r = G.CAM_DIST * Math.cos(G.CAM_PITCH);
var _ox = Math.sin(G.CAM_YAW) * _r;
var _oz = Math.cos(G.CAM_YAW) * _r;
cam.position.set(P.x + sx + _ox, 同原来, P.z + _oz + sz);
```

★ `CAM_YAW = 0` 时 `_ox = 0、_oz = _r` → **和现在一模一样** ✓ 零回归 ✓

## 3. 最关键的一条：**移动方向要跟着镜头转**

现在是"按 W = 往屏幕上方走 = 世界 -Z"。镜头一转，如果还按世界方向走，
玩家会觉得"我按上，人却斜着走" ✗ —— 这是这类功能最容易翻车的地方 ✓

所以移动输入要先按镜头角度转一次（在 `var ix = jx, iz = jy;` 之后、算长度之前）：

```js
var _cy = Math.cos(G.CAM_YAW), _sy = Math.sin(G.CAM_YAW);
var _nx = ix * _cy - iz * _sy;     /* 世界方向 = 输入方向绕镜头转 */
var _nz = ix * _sy + iz * _cy;
ix = _nx; iz = _nz;
```

★ `CAM_YAW = 0` → `_cy=1,_sy=0` → 原值 ✓ 又是零回归 ✓

**自动战斗不受影响**：AI 是直接改 `jx/jy` / 直接朝怪走（世界坐标），
转完镜头它照样朝怪走 ✓ 不会变成"斜着追" ✓

## 4. 按钮与手势

### 4.1 按钮

放在右上角「俯瞰」旁边（同一排，样式一致）：

```
[俯瞰] [转视角]   ← 关着时：灰（锁定）
 [俯瞰] [转视角●]  ← 开着时：金色高亮 + 一个小"旋转"图标
```

| 操作 | 行为 |
|---|---|
| 点一下（关→开）| 进入可旋转状态，提示「拖动转视角 · 再点锁定」|
| 点一下（开→关）| **锁定**在当前角度（不弹回 ✓）|
| **长按 1 秒** | 回正到 `CAM_YAW = 0`（并锁定）|

### 4.2 手势（不能和"走路/攻击"打架）

现在：**左半屏拖动 = 走**，右下角是攻击/跳跃/自动按钮 ✓

| 状态 | 手势 |
|---|---|
| 关闭（锁定）| 一切照旧（左半屏走、右下攻击）✗ 不响应旋转 ✓ |
| **开启** | · **右半屏单指拖动 = 转视角**（上下拖动改俯角，左右改水平角）<br>· 左半屏**照旧走路** ✓ 互不干扰<br>· 双指拖动（任意位置）= 转视角（给习惯两指的人 ✓）|

- 水平角：**不限制**（可以 360° 转）
- 俯角：限制在 `0.55 ~ 1.25` 之间（太低会贴地、太高变俯视图 ✗ 都不好看）
- 转的时候**不打断走路**：一边走一边转也要能用 ✓

### 4.3 记忆

- 角度存本地（`localStorage`，platform 层读写 ✗ core 不碰 ✓）
- 下次进游戏**保持上次的角度**（锁定的意思就是"以后都这样"✓）
- 想回默认 → 长按 1 秒 ✓

## 5. 还要跟着改的几处（漏一处就会出怪事）

| 位置 | 影响 | 处理 |
|---|---|---|
| 移动输入 | 上面 §3 | 输入向量按 yaw 旋转 ✓ |
| 镜头抖动 `sx/sz` | 抖动方向是世界轴 ✗ 转完镜头会变成"斜着抖" | 抖动也按 yaw 旋转（内部小改 ✓）|
| 屏幕提示「左半屏拖动 = 走」| 文案没错 ✓ 不用改 | — |
| 攻击方向 | 用的是玩家朝向 `P.yaw`（世界坐标）✓ 不受影响 | 不用改 |
| 弓的抛射物 | 用玩家朝向 ✓ | 不用改 |
| 妖兽/掉落/飘字的屏幕投影 | 都是 `project(cam)` ✓ 自动跟着转 | 不用改 |
| 键位自定义（按钮拖动）| 新按钮也走同一套位置逻辑 ✓ 建议**可拖动**（和攻击键一样）| 复用现成的键位系统 |
| 自动战斗「后撤」| `faceLock` 锁的是世界朝向 ✓ | 不用改 |
| 断线重连 | 角度是本地状态 ✓ 不影响握手 | 不用改 |

## 6. 边界情况

| 场景 | 处理 |
|---|---|
| 转视角时正好在攻击/跳跃 | 允许 ✓ 互不影响 |
| 转视角时打开了菜单 | 菜单挡住 → 手势被菜单吃掉 ✓ 关掉菜单继续 |
| 手机横竖屏切换 | 角度不变，重新算半径 ✓ |
| 死后 / 观战 | 照常能转（不影响复活）|
| 有的手机没有 localStorage | 读不到就用默认 0 ✓ 不报错 |
| 转到"背对角色" | 允许 ✓ 此时按 W 会朝镜头方向走（因为相机在这个方向 ✓ 符合直觉）|

## 8. 需要你拍板的 3 件事

1. **再点一次是"停在当前角度"还是"回到默认"？**
   我推荐：**停在当前**（叫"锁定"更贴切 ✓），回默认用长按 1 秒。
2. **手势用哪只手？**
   我推荐：开启后**右半屏单指拖动**转 + 双指任意位置也能转（左半屏继续走路 ✓ 不打架）。
3. **要不要上下俯仰？**
   我推荐：**要**，但限制在 0.55~1.25（太低贴地、太高俯视都不好看）。
   如果你只想要水平转，我就把上下关掉（更简单、更不容易误操作）。

### 9.6 round498：手感（用户反馈"不流畅"）

**根因**：拖动时每一帧都把角度【直接设成】手指位置 ✗
触摸事件是一阵一阵来的 → 角度一小步一小步跳 ✗ 看着就是一顿一顿 ✓

**修**：拖动只改【目标角】`CAM_YAW_T / CAM_PITCH_T` ✓
渲染时用指数平滑追（`camStep(dt)`，约 60ms 追平）✓
和相机高度那个 `_camY` 缓动是同一套思路 ✓

顺带：灵敏度 0.0055 → **0.0060**（100px ≈ 34°，转一圈不用拖太远）；
读档 / 回正时【直接就位】✗ 不从 0 慢慢转过去 ✓

测试加了 3 条：拖动后当前角**滞后**于目标 → 400ms 内**追上** → 手感平滑 ✓

### 9.7 round499：真 bug（"抖 + 拖不动"的根因）

**症状**：拖动时视角来回抖，而且感觉拖不太动。

**根因（用真实触摸事件量出来的）**：
`uiDragInit()` 是**每 100ms 调一次**的（为了保证按钮一定挂上 ✓），
而我在里面调了 `camLoadSaved()` → **每 100ms 把视角读回上次存的角度** ✗
→ 一边拖一边被拽回去 → 抖 + 拖不动 ✓✓ 一字不差。

实测数据（修复前后同一段 200px 拖动）：

| 第几步 | 修复前 yaw | 修复后 yaw |
|---|---|---|
| 1 | 0.12 | 0.12 |
| 2 | 0.24 | 0.24 |
| 3 | **0.24（卡住）** | 0.36 |
| 4 | **0.24（卡住）** | 0.48 |
| 5 | **0.24（卡住）** | 0.60 |
| 10 | 0.48 | 1.20 |

**修**：读档只做一次（`CAMROT.loaded` 守卫 ✓），存档照旧每 400ms 写 ✓

★ 教训：往一个"幂等初始化函数"里加东西前，先确认它到底被调用几次 ✗

现在 200px 拖动 = 1.2 弧度 ≈ 69°，每 20px 稳定 +0.12 ✓ 又跟手又平滑。

### 9.8 round501：真 bug（"转动视角后自动战斗出问题"）

**根因**：
`autoTick()` 往 `jx/jy` 里写的是**世界方向**（它用 `autoFacing(jx, jy)` 直接算朝向，
说明它自己就是世界坐标 ✓），而我 round497 在移动那里**又按镜头转了一次** ✗
→ 转完视角后 AI 的"朝怪走"被转歪 → 绕着怪转圈 / 越走越远 ✓

**修**：只转**玩家自己推的**方向 ✗ AI 写的不转 ✓
判据就是现成的 `AUTO.setInput`（= 这一帧的方向是 AI 写的 ✓）：

```js
var _autoDrv = (typeof AUTO !== 'undefined' && AUTO && AUTO.setInput);
if (CAM_YAW && !_autoDrv) { /* 旋转 ix/iz */ }
```

**测试**（`tools/test_camera.js` 新增一条）：
镜头转 90° + 模拟 AI 写"世界 +X" → 人必须**朝 +X 走**（不被转成 +Z）✓
