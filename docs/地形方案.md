## 2. 高度

### 2.1 数据结构

```
每格存三个值：

   h    高度（浮点 ✗ 单位 = "格"）✗ 0.0 = 地面 ✓
        范围 −1.0 ~ 5.x
        ★ 为什么是浮点不是整数：用户要求"不要每个都很准确的一格"✓
          视觉上高低不一才自然 ✓ 见 §2.5

   mat  材质（草/土/石/砖/木/冰/泥）
   sl   斜坡方向（0 = 不是斜坡）
```

### 2.2 一格多大（给范围，手感优先）

```
最小值：0.50 世界单位（再小 ✗ 人会卡在缝里 ✓）
最大值：0.80 世界单位（再大 ✗ 一格走两步就没意义了 ✓）
默认值：0.62（= 现在的 G.TS ✓）

人物碰撞箱 0.6 × 0.5（不变 ✓）
人物高 2 格（默认 = 1.24 世界单位 ✓）

★ 为什么给范围而不是定死一个数：
  这个值最影响的是【手感】✗ 算不出来 ✓
  做完 P0 进游戏走一圈 ✗ 嫌大就往 0.55 调 ✗ 嫌小往 0.70 ✓
  ★ 但改它要同时改客户端和服务端（worldgen.py 的 TS ✓）
```

### 2.3 高度怎么生成

```
h = 0
  + 低频噪声 A（波长 ~14 格）→ 0 ~ 2 格      ← 大起伏
  + 低频噪声 B（波长 ~5 格）→ 0 ~ 1 格       ← 小台阶
  + 小山（§2.6）
  + 每格独立抖动 ±0.12 格                    ← ★ "不要每个都很准确"✓

★ 只用【格子坐标 + 世界种子】算 ✗ 不依赖别的状态 ✓
★ 安全区（±15 单位）强制拍平成 0.0 ✗ 堡垒里不能有坑 ✓
```

### 2.4 渲染

```
每个区块（32×32 格）合并成一个 BufferGeometry：
  · 顶面：每格 1 个四边形（★ 高度不同 ✗ 顶面不在同一水平面 ✓ 所以不能合并成大片 ✓）
  · 侧面：只画【比邻居高】的部分 ✗ 被挡住的完全不生成 ✓
  · 底面：不画

估算：1024 格 → 顶面 2048 三角形 + 侧面约 700 → 一个区块 ~2700 三角形
     视野内约 12 个区块 → 3.2 万三角形 ✓ 手机没问题 ✓

★ 注意：加了"每格抖动"之后，顶面不能再用 greedy meshing 合并成大片 ✗
  每格是独立高度 ✓ 只能一格一个四边形 ✓
  → 三角形数比纯方块地形多 ~40% ✗ 但还能接受 ✓
  → 如果手机上不够：把抖动做在【顶点色明暗】上 ✗ 不改几何 ✓（备用方案 ✓）
```

### 2.5 格子高低不一（用户要求）

```
每个格子的顶面高度 = h + jitter
   jitter ∈ [−0.12, +0.12] 格（由格子哈希决定 ✗ 不是随机数 ✓ 保证两边一致）

视觉效果：
  · 一片草地看起来是"微微起伏"✗ 不是一块平板 ✓
  · 相邻格最多差 0.24 格 ✗ 肉眼几乎不觉得是"坎"✓

玩法影响：
  · 它【参与】高度差计算 ✓ 所以有些地方"看着一样高，其实差一点"✓
  · 走：落差 ≤ 0.35 直接迈（盖住抖动 ✓ 不会有走路被卡住的问题 ✓）
  · 跳：跳 1 格 ✓（见 §3.4）
```

### 2.6 小山（随机、最高 5 层、不固定样式）

```
★ 用户要求："小山可以随机一点最高 5 层，不用固定样式"

做法（三层叠加）：↓

① 选山心：按区块哈希定一个位置（不是每块都有山，约 1/6 的区块有）
② 选高度：HILL_H = 随机 2 ~ 5（整数）
③ 选半径：R = 3 ~ 6 格（越高越大）
④ 形状：不是正圆 ✗ 半径带角度噪声
       r(θ) = R × (1 + 0.25 sin(2θ+a) + 0.15 sin(3θ+b) + 0.10 sin(5θ+c))
       → 山腰是"不规则的一圈一圈"✗ 每座山都不一样 ✓
⑤ 高度衰减：h = HILL_H × (1 − dist/r(θ))^1.4
       → 指数 1.4 让山腰更缓、山顶更尖 ✓（比线性像山 ✓）
⑥ 外圈自动铺一圈斜坡（§2.7）✗ 保证爬得上去 ✓
⑦ 山顶 1~3 格放石头（可拆 ✓）

★ 反例（我第一版就是这么画的 ✗ 改了四版）：
  手排格子 / 正圆锥 → 出来是"一堆盒子"或者"一个土坟"✓ 都不像山 ✓
```

### 2.7 斜坡（不用跳就能走上去）

```
斜坡也是【一格】✗ 只是顶面是斜面 ✓
  数据：h（低端高度）+ sl（升高方向 N/E/S/W）
  视觉：一格宽的斜板，从 h 抬到 h+1
  走进去：人物 Y 在这一格内线性插值 ✓ 不减速 ✓ 不用跳 ✓

★ 生成规则：山体外圈自动铺 ✓
  （不铺的话会生成"爬不上去的孤峰"✗ 玩家会很烦 ✓）
★ 斜坡上的掉落：不触发 ✗ 高度是连续的 ✓
```

## 3. 人物与碰撞

### 3.1 占位

```
人物占两格：脚下那格（实心）+ 头上那格（必须是空气）
→ 所以 1 格高的洞钻不进去 ✓ 这是对的 ✓
```

### 3.2 上下坡判定（含抖动）

```
落差 = 目标格高度 − 当前格高度（都是浮点 ✗ 含 jitter ✓）

  落差 ≤ +0.35        ：直接迈上去（小坎 ✓ 盖住抖动 ✓ 不会卡住 ✓）
  +0.35 < 落差 ≤ +1.15：要跳（见 §3.4）
  落差 > +1.15        ：上不去 ✗ 找斜坡（§2.7）或破坏（§5）
  落差 ≤ 0            ：走下去（掉不掉血看 §4）
  斜坡格              ：无视落差 ✗ 直接走 ✓
```

### 3.3 碰撞顺序

```
1. 算目标位置 → 落在哪一格
2. 那一格 + 头顶那格有没有【实心物件】（树/房子）
3. 落差能不能过（§3.2）
4. 都过了才真的移动
```

### 3.4 跳跃（只能跳 1 格）

```
按钮：攻击键【左下角】✗ 直径约攻击键的 60% ✓ 拇指不用挪 ✓

参数（初版）：
  跳跃高度     1.15 格   ← ★ 关键：不是 1.00
  滞空时间     0.35 秒
  起跳速度     4.2（水平跑速 4.4 ✗ 跳不会变快 ✓）
  冷却         0.15 秒（不能连跳刷位移 ✓）
  空中控制     可以转向 ✗ 但不能加速 ✓

★ 为什么跳跃高度取 1.15 而不是 1.00：
  格子有 ±0.12 的抖动 ✗ "一层台阶"的实际落差会在 0.76 ~ 1.24 之间 ✓
  取 1.00 的话 → 1.1 的台阶跳不上去 ✓ 玩家会觉得"明明一样高"
  取 1.15 的话 → 一层（≤1.12）永远跳得上去 ✓
                两层（≥1.76）永远跳不上去 ✓
                中间高度（1.2~1.7，靠抖动产生的）→ 跳不上 ✗ 要斜坡 ✓
  ★ 这样既满足"只能跳一格"✗ 又不会因为抖动产生"玄学上不去"✓

能干什么：
  ✓ 上 1 格高的台子（走路也行 ✗ 跳更快）
  ✓ 跨过 1 格宽的坑（2 格跳不过 ✓）
  ✓ 从高处跳下去（自己选 ✗ 但会掉血 ✓）

跳不上去：
  ✗ 2 格以上的台子
  ✗ 头顶有东西（洞里跳不起来）
  ✗ 站在冰上：起跳会滑开（§6.1）
```

## 4. 掉落伤害（每格 5 点）

### 4.1 规则（按用户决定）

```
落差 ≥ 3.0 格才掉血 ✓
伤害 = (floor(落差) − 2) × 5 点

  落差 3 → 5 点
  落差 4 → 10 点
  落差 5 → 15 点
  落差 6 → 20 点

★ 落点下面是水：不掉血 ✗ 但移速变慢（沼泽 ✓）
★ 落点被占（墙/树）：人卡边上 ✗ 不算掉落 ✓
★ 斜坡不触发 ✗ 高度连续 ✓
★ 判定放服务端 ✗ 客户端只做表现 ✓
```

### 4.2 ★ 一个必须提的问题：5 点在高等级等于没有

```
血量公式（server/mobs.py level_hp ✓）= 100 + 22L + 0.6L²

等级   血量    摔3格(5点)   摔6格(20点)
  1    123     4.07%       16.26%      ← 疼 ✓
 10    380     1.32%        5.26%      ← 还行
 30   1300     0.38%        1.54%      ← 没感觉 ✗
 60   3580     0.14%        0.56%      ← 完全没感觉 ✗
 68   4370     0.11%        0.46%      ← 完全没感觉 ✗

★ 也就是说：按"固定 5 点"做 ✗ 60 级号从 5 层摔到坑里 = 掉 15 点 = 0.4%
  玩家根本不会为了地形绕路 ✓ 地形就白做了 ✓

建议改法（只改一个公式 ✗ 1 级还是 5 点 ✓）：

   每格伤害 = max(5, 1.5% × 最大生命)

   等级   每格伤害   摔3格    摔6格
     1      5        5       20    ← 和你说的一模一样 ✓
     5      5        5       20    ← 一模一样 ✓
    10      6        6       24
    30     20       20       80    ← 约 6% 血 ✓ 疼 ✓
    60     54       54      216    ← 约 6% 血 ✓ 疼 ✓

★ 1~5 级完全是"你说的 5 点"✗ 高等级才慢慢加上去 ✓
  如果你就是要【纯固定 5 点】✗ 改一个常数就行 ✓ 我先按这个建议做也可以 ✓
```

## 5. 破坏

### 5.1 打谁

```
挥刀时【先判地形】✗ 顺序很重要 ✓
1. 前方扇形内（ATK_ARC 60° ✗ ATK_RANGE 2.4）有没有可破坏的格子/物件
2. 有 → 打它（扣耐久 ✗ 不掉怪血）
3. 没有 → 照旧打怪

★ 不先判地形 → 站在墙前打僵尸 ✗ 墙永远拆不掉 ✓
★ 多人打同一格：耐久共享 ✗ 越快拆完 ✓
```

### 5.2 材质表

| 材质 | 打几下碎 | 出现在哪 | 碎了掉什么 |
|---|---|---|---|
| 草丛 / 泥土 | **1** | 地面层 | 什么都不掉（变坑） |
| 木头 | **2** | 树、枯树、木栅栏、木墙 | 木头 ×1~2 |
| 冰 | **2** | 冰原 | 碎冰（只做视觉） |
| 砖 | **4** | 房子墙、城区废墟 | 碎砖 ×1 |
| 石头 | **6** | 山顶、岩石、石台 | 石块 ×1（低概率） |
| 混凝土 | **8** | 军事区（以后） | 铁屑（以后） |

```
★ 为什么"草 1 下、石 6 下"：
  草土 = 软化地形 ✗ 一下掀掉（挖战壕 ✓ 开近路 ✓）
  石头 = 战略资源 ✗ 6 下 = "想拆山得花时间" ✓
  → 玩家自然形成"绕路 vs 挖穿"的选择 ✓ 这就是玩法 ✓
```

### 5.3 往下只能破坏一层（用户决定）

```
地面（h = 0）被打碎 → 变成坑（h = −1）✗ 能站进去 ✓

★ 再打这个坑 → 【不会再往下挖】✗ 到底了 ✓
  表现：坑底变石头材质 ✗ 打它只掉碎屑不掉深度 ✓

台地/墙被打碎：
  · 那一格消失 ✗ 上面的格子【塌一层】✓
  · 只塌一格 ✗ 不连锁（免得半座山塌掉 ✓）

为什么只给一层：
  能无限往下挖的话 ✗ 地图会被挖成迷宫 ✓
  而且掉进坑里出不来会变成很烦的体验 ✓
```

### 5.4 现有的树和建筑

```
这两类现在是【独立 mesh】✗ 已经在 solids[] 里 ✓
  ① 给每个物件加 hp（按材质查表）
  ② 打到 0 → 播放倒下动画（§5.8）+ 从 solids[] 删掉 + 记住"这棵没了"
  ③ 服务端记住（存库 ✓ 见 §5.7）
```

### 5.5 破坏后的样子

```
· 地面层打碎 → 坑（h 从 0 到 −1）✗ 只能一层 ✓
· 台地/墙打碎 → 那格消失 ✗ 上面塌一层 ✓
· 树 → 倒下（§5.8）
· 房子墙 → 消失 ✗ 房子不塌（简化 ✓）
```

### 5.6 破坏动画（四层，见 `terrain-break.png`）

```
① 命中抖动        【每一刀】模型沿受击方向位移 2px ✗ 0.08 秒回弹 ✓
② 碎屑粒子        【每一刀】3~5 个小方块抛出去 0.5 秒 ✓ 对象池 32 个 ✓
③ 裂纹贴图        【过阈值】三张图（完好/裂一道/裂一片）✗ 1/3、2/3 各换一次 ✓
④ 碎裂 + 尘烟     【最后一下】8~12 块抛物线飞散 ✗ 落地淡出 ✗ 一团尘烟 ✓

耗时目标：普通一刀 ~3ms ✗ 碎的那刀 ~8ms ✓

三条铁律：
  ★ 抖动和碎屑必须【同帧】✗ 有延迟就没打击感 ✓
  ★ 裂纹三张图就够 ✗ 不用做动画 ✓
  ★ 碎块落地【马上消失】✗ 只留一块碎石地纹理 ✓
```

### 5.7 ★ 破坏临时存库 + 自己慢慢恢复（新需求）

```
用户原话："破坏临时存库，我希望在没有人时会自己慢慢恢复"

设计：不跑定时器 ✗ 【惰性计算】✓

存库（新表 terrain_damage）：
   x, z, mat, hp_saved, last_hit_ms

恢复怎么算（读到的时候算 ✗ 不用每秒扫描全图 ✓）：

   hp_now = min(hp_max, hp_saved + (now − last_hit_ms) × 每秒恢复量)

   每秒恢复量 = 1 / 完全恢复秒数
   完全恢复秒数 = 20 分钟（可调 ✗ 见下面）

  → 一格石头 6 血 ✗ 20 分钟回满 ✗ 也就是 3.3 分钟回 1 下 ✓
  → 一棵树 2 血 ✗ 6.7 分钟回满 ✓

★ 为什么这样最省：
  不跑定时器 ✓ 不扫全图 ✓ 100 万格被破坏也几乎不花 CPU ✓
  只在【区块加载】和【玩家看得见这块】的时候算一次 ✓

★ "看不见的时候"和"看得见的时候"表现要一致：
  看得见时：每 2 秒重算一次这一区块的可见格 ✗ 玩家能看到"裂缝慢慢合上"✓
  看不见时：不重算 ✗ 下次加载时一次算对 ✓

★ 恢复完成后：删掉那一行记录 ✗ 表又变空 ✓
★ 上限：一张表最多 5 万行（超过就强制恢复最老的 ✓ 防库暴涨 ✓）

★ 要不要"被破坏的地方长回来"这种视觉过渡：
  hp 回升 → 裂纹贴图从"裂一片"回到"裂一道"→ 回到完好 ✓
  坑变成平地 → 用 0.5 秒的"填平"动画 ✓（可选 ✗ 见待确认 ✓）
```

### 5.8 ★ 树倒下（用户决定：倒地动画、不砸人、再打消失）

```
三态：

  ① 站着      ─── 打 2 下（木头材质）→ 进入 ②
  ② 倒着      ─── 倒地动画 0.5 秒 ✗ 仍占地方（挡住路 ✓）
                  再打 1 下 → 进入 ③
  ③ 消失      ─── 掉落木材 ×1~2 ✗ 消失 ✓

倒地动画怎么演（0.5 秒）：
  0.00s  树干整体朝【受击反方向】倾倒（绕底部那条边旋转）
  0.00s  同时树根处扬一圈尘土
  0.35s  转到 75° ✗ 速度开始变慢 ✓
  0.42s  贴地时【弹一下】（10° → 0°）✗ 有重量感 ✓
  0.50s  完全躺平（90°）✗ 扬尘扩散消失 ✓
        + 一声闷响 + 树叶沙沙

★ 为什么不砸人（用户决定）：
  砸人的话 ✗ 玩家会被自己砍的树卡住 / 掉血 ✓ 很烦 ✓
★ 倒下的树为什么还要挡路：
```

## 13. ★ 第三轮改动（用户 2026-10-17 实机试玩后）

```
   3.高度不一致的方块只会出现在有小山坡的地形，平地上的方块都是一个高低大小，
     山的样式多样点，也可以有悬崖峭壁的山"
```

### 13.1 斜坡去掉了

```
terrain.py / game.js 的 slope_of() 恒返回 0 ✓
★ 函数没删 ✗ 交叉验证测试还要比这一项 ✓ 以后想加回来只改那一处 ✓

爬山改成【跳 1 格】✓
  缓山：每格落差 1 → 跳得上去 ✓
  悬崖山：每格落差 2~3 → 跳不上去 ✗ 要绕到缓的一边 ✓
  （实测：997 处 +1 台阶 / 100 处 +2 峭壁 / 6 处 +3 ✓ 比例合适 ✓）
```

### 13.2 ★★ 僵尸穿模（我引入的真 bug）★★

```
现象：用户"僵尸怎么无视方块可以直接穿模了"

根因（两条叠在一起）：
  ① 服务端 _mob_step 只查 worldgen.blocked（树/房子那些 2D 盒子）
     完全没查【地形高度】✗ 我给玩家加了 terrainStepOk ✗ 僵尸没加 ✓
     → 玩家爬不上去的峭壁，僵尸直接走上去 ✓ 看着就是穿模 ✓
  ② 客户端把僵尸【永远画在 y=0】✗ 走进山里整个人陷进去 ✓

修法：
  ① 服务端：_mob_step 里加地形判定 ✓ 和玩家【同一套规矩】✓
     落差 ≤ STEP_JUMP(1.15) → 跳上去 ✓ 更大 → 过不去 ✓
  ② 客户端：僵尸 Y 跟着 terYAt 走 ✗ 落差 1 格时补 0.3 秒跳跃弧线 ✓
     ★ 用纯函数自己算 ✗ 不需要服务器多发字段 ✓ 这正是确定性地形的好处 ✓

验证：模拟"让僵尸一直朝山里走"✗ 四个方向全部被挡在外面 ✓
      （能到 h=0~1 ✗ 山高 4 层 ✓ 上不去 ✓）
```

### 13.3 平地统一 + 山的样式

```
① 去掉【低频噪声】和【每格抖动】✓
   → 平地 100% 是 h=0 ✗ 一个高低 ✓（实测 89~96% 的格子是 0 层）
   ★ 材质（草/土/石）还是按噪声分 ✗ 但那只影响颜色 ✓ 不影响高度 ✓
     用户要的是"高低大小一样"✗ 不是"颜色一样"✓

② 山的形状：每座山 = 【3 个偏心圆叠出来】✓
   ★ 为什么不用 sin 做角度噪声：两边语言算不准（libm 差 1ulp ✗ 全错）
   → 用三个偏移的圆叠 ✗ 轮廓天然是歪的 ✓ 只用 sqrt ✓ 两边一致 ✓

③ 两种山（各占一部分）：
   缓山   半径 = 1.35×高 + 1.2  → 每格落差 ≈ 1 ✓ 跳得上去 ✓
   悬崖山 半径 = 0.45×高 + 1.2  → 每格落差 2~3 ✓ 峭壁 ✓ 要绕路 ✓
   另有一层【小土包】（12×12 格一个 ✗ 1~2 层）让荒野不那么平 ✓

④ 高度分布（实测 160×160 格）：
   h=0  92.1%   h=1  4.0%   h=2  1.9%   h=3  0.9%   h=4  0.7%   h=5  0.4%
```

### 13.4 掉落伤害（用户定：纯固定 5 点）

```
  · 服务端扣血（客户端只报落差 ✗ 服务端夹到 0~60 ✓）
  · 摔死也掉魔气（和被打死同一条规矩 ✓）
★ 已知副作用：60 级（3580 血）摔一下 5 点 = 0.14% ✗ 基本没感觉
  用户已确认要固定值 ✓ 所以先这样 ✓ 以后想改只改一个常数 ✓
```
