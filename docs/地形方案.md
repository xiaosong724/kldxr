## 1. 现状（改之前是这个样子的）

```
渲染     Three.js r149 ✗ 本来就是 3D 场景 ✓
         相机：俯角 58° ✗ 距离 21 ✗ 固定跟随 ✓（所以"高度"就是真实的 Y 轴 ✓）
地面     一片大平面（PlaneGeometry）跟着玩家走 ✗
         地貌靠【顶点色】染出来（草/土/石/路的大色块 ✓）
         没有任何高度 ✗ 也不会被破坏 ✓
物件     树 / 房子 / 石头 / 废车 / 围栏 = 独立的 mesh ✗
         按【格子哈希】确定性生成（谁算都一样 ✓）
碰撞     2D 盒子（只有 x / z ✗ 没有 y）✗
         客户端 solids[] + 服务端 worldgen.py 各算一遍 ✗ 必须完全一致 ✓
移动     客户端算位置 ✗ 服务端做校验（moveT / moveBad / suspect）✓
```

**三条硬约束**（动手前必须记住）：

```
① 地形生成是【确定性的】✗ 客户端和服务端各算一遍 ✗ 结果必须一模一样 ✓
   改了 game.js 的生成规则，worldgen.py 必须同步改 ✗
   否则服务器认为"这里有墙"而客户端看到一条路 ✗ 僵尸会穿墙 ✓
   （第 41 轮就是为这个才写了 worldgen.py ✓ 还有一条交叉验证测试 ✓）

② 手机性能 ✗ 现在 MOB_MAX = 60 就是为了别掉帧 ✓
   1024 格×4 个面 = 4096 个面 ✗ 一个区块就这么多 ✓
   → 必须【合并几何】+ 只画露出来的面 ✗ 一格一个 mesh 直接完蛋 ✓

③ 破坏是【会改变世界】的操作 ✗ 必须存库 ✓
   不然掉线重登墙又长回来了 ✓
```

## 2. 高度（按格子算）

### 2.1 数据

```
每一格存两个数：
   h    高度（整数 ✗ 层）✗ 0 = 地面 ✓
   mat  材质（草 / 土 / 石 / 砖 / 木 / 冰 / 泥）

高度范围：0 ~ 5 层
  ★ 为什么只到 5：再高会挡住视野 ✗ 相机俯角 58° 看不到墙后面 ✓
    而且玩家角色只有 2 格高 ✗ 5 层 = 2.5 个人 ✓ 已经很有气势 ✓
```

### 2.2 一格多大

```
候选 A（推荐）：一格 = 0.62 世界单位（沿用现在的 G.TS ✓）
   人物碰撞箱 0.6 × 0.5（完全不变 ✓）
   人物高 2 格 = 1.24
   → 现有所有数值都不用改 ✓ 风险最小 ✓

候选 B：一格 = 1.24（2 × TS）
   一格看着更"厚"✗ 但人物会变成 1 格宽 2 格高 → 比例更瘦长 ✓
```

★ 推荐 A ✗ 因为它不动任何现有常数 ✓ 出问题能立刻退回。

### 2.3 高度怎么生成

```
h = 0
  + 低频噪声 A（波长 ~14 格）→ 0 ~ 2 层     ← 缓坡，大起伏
  + 低频噪声 B（波长 ~5 格） → 0 ~ 1 层     ← 小台阶
  + 台地规则：噪声值 > 阈值 → 一次性抬到 3~5 层  ← 少数高地（能居高临下）

★ 关键：只用【格子坐标 + 世界种子】算 ✗ 不依赖任何别的状态 ✓
  这样客户端和服务端算出来一定一样 ✓

★ 安全区（±15 单位）强制拍平成 0 ✗ 不能在堡垒里挖出坑 ✓
```

### 2.4 渲染

```
每个区块（32×32 格）合并成一个 BufferGeometry：
  · 顶面：每格 1 个四边形（2 个三角形）
  · 侧面：只画【比邻居高】的那部分 ✗ 被挡住的完全不生成 ✓
    （平地上 0 个侧面 ✓ 台地边缘才有 ✓ 省很多 ✓）
  · 底面：不画（看不见 ✓）

估算：32×32 = 1024 格 ✗ 顶面 2048 三角形
      + 侧面（平均 15% 的格子露边）≈ 600 三角形
      一个区块 ~2600 三角形 ✗ 手机上完全没问题 ✓
      视野内约 12 个区块 → 3 万三角形 ✓ 和现在画树差不多 ✓
```

## 3. 人物与碰撞（两格高）

### 3.1 占位

```
人物占两格：脚下那格（h_stand）+ 头上那格（h_stand+1）
  脚下那格：一定是实心的（站在上面 ✓）
  头上那格：必须是【空】的 ✗ 否则钻不进去（比如 1 格高的洞）✓

举例：
   ┌───┐  ← 头顶格（必须是空气）
   │ 人│
   ├───┤  ← 脚底格（实心地面）
   │地面│
   └───┘
```

### 3.2 上下坡

```
落差 = 目标格高度 − 当前格高度

  落差 ≤ 0      ：走下去（不用判断 ✗ 直接走 ✓ 掉不掉血看 §4）
  落差 = +1     ：自动迈上去（台阶 ✓ 不减速 ✓）
  落差 = +2     ：★ 要看有没有"跳跃/攀爬"能力（见 §7 待拍板）
  落差 ≥ +3     ：走不过去（墙 ✓ 得先破坏或者绕路 ✓）
```

### 3.3 碰撞判定顺序（每次移动）

```
1. 算目标位置 → 落在哪一格
2. 那一格（和头顶那格）有没有【实心物件】   ← 树/房子，和现在一样
3. 高度落差能不能过（§3.2）
4. 都过了才真的移动 ✓
```

## 4. 掉落（落差三格以上掉血）

```
落地时算一次：落差 = 起跳格高度 − 落点格高度

  落差 ≤ 2   ：不掉血（跳下一层窗台 ✓ 不疼 ✓）
  落差 ≥ 3   ：伤害 = (落差 − 2) × 8% 最大生命
              上限 60%（再高也不会一击死 ✓）

举例（最大生命 200）：
  落差 3 → 8%  = 16 血
  落差 4 → 16% = 32 血
  落差 5 → 24% = 48 血
  落差 8+ → 60% 封顶 = 120 血

★ 落点下面是【水】：不掉血 ✗ 但移速变慢（沼泽 ✓）
★ 落点被占（墙/树）：人卡在边上 ✗ 不算掉落 ✓（挪到最近能站的地方）
```

**为什么是"8% ×（落差−2）"**：

```
· 按【百分比】不按固定值 → 低级号和高级号都不会被一击秒 ✓
· 8% 这个数：落差 3 = 掉 1/12 血 ✗ 疼但能接受 ✓
              落差 6 = 掉 1/3 血 ✗ 开始要认真考虑路线 ✓
· 上限 60%：从再高的地方跳下来也留 40% ✗ 不会变成"摔死"游戏 ✓
```

★ **判定放在服务端** ✗ 客户端只做表现 ✓（不然改客户端就能免伤 ✓）

## 5. 破坏

### 5.1 打谁

```
挥刀时【先判地形】✗ 顺序很重要 ✓

1. 前方扇形内（ATK_ARC 60°、ATK_RANGE 2.4）有没有【可破坏的格子/物件】
2. 有 → 打它（扣耐久 ✗ 不掉怪血 ✓ 打到碎为止）
3. 没有 → 照旧打怪

★ 为什么先判地形：不然站在墙前面打僵尸 ✗ 墙永远拆不掉 ✓
★ 多人一起打同一格：耐久是【共享】的 ✗ 越快拆完 ✓
```

### 5.2 材质表

| 材质 | 打几下碎 | 出现在哪 | 碎了掉什么 |
|---|---|---|---|
| 草丛 / 泥土 | **1** | 全地图地面层 | 什么都不掉（直接变坑） |
| 木头 | **2** | 树、枯树、木栅栏、木墙 | 木头 ×1~2 |
| 冰 | **2** | 冰原 | 碎冰（很快化掉 ✗ 只有视觉效果） |
| 砖 | **4** | 房子墙、城区废墟 | 碎砖 ×1 |
| 石头 | **6** | 石台、岩石、山体 | 石块 ×1（低概率） |
| 混凝土 | **8** | 军事区（以后） | 铁屑（以后） |

```
★ 为什么"草 1 下、石 6 下"：
  草土是【软化地形】✗ 一下就该掀掉 → 挖战壕、开近路 ✓
  石头是【战略资源】✗ 6 下意味着"想拆山得花时间"✓
  → 玩家会自然形成"绕路 vs 挖穿"的选择 ✓ 这就是玩法 ✓
```

### 5.3 破坏后的样子

```
· 地面层（h=0）被打碎 → 变成【坑】（h 降到 −1）✗ 能站进去 ✓
  ★ 坑不叠加：不能无限往下挖（挖到底就变石头 ✓）

· 台地/墙被打碎 → 那一格消失 ✗ 上面的格子【塌下来】✓
  ★ 塌落只掉一格（不连锁）✗ 免得半座山塌掉 ✓

· 树被打碎 → 整棵树消失 ✗ 掉 1~2 个木材 ✓

· 房子墙被打碎 → 墙消失 ✗ 房子【不会塌】✓（简化 ✓）
```

### 5.4 现有的树和建筑

```
现在这两类都是【独立 mesh】✗ 已经在 solids[] 里 ✓

改动：
  ① 给每个物件加一个 hp（按材质查表 ✓）
  ② 打到 hp 归零 → 从 solids[] 里删掉 + 播放碎裂动画 + mesh 销毁
  ③ 服务端要记住"这棵树没了"（存库 ✓ 见 §8）
```

### 5.5 破坏动画（三层）

```
第 1 层 · 命中反馈（每一刀都有，0.1 秒）
  · 方块整体抖 2px（朝向玩家反方向）
  · 掉 2~4 个小碎屑（按材质颜色）
  · 一声"笃"（材质不同音调不同：木头闷、石头脆、冰亮）

第 2 层 · 裂纹（耐久到 1/3、2/3 时切换贴图）
  · 三个阶段的裂纹贴图（完好的 / 裂一道 / 裂一片）
  · 切换时掉一点灰

第 3 层 · 碎裂（耐久归零，0.6 秒）
  · 方块炸成 6~10 个小方块
  · 抛物线飞散 ✗ 重力下落 ✗ 落地后 0.4 秒淡出
  · 原地留一块"碎石地"纹理
  · 一声闷响 + 一小片烟尘
```

### 5.6 碎块怎么画（性能）

```
★ 不能用"每次创建几十个 Mesh" ✗ 手机上会卡 ✓

做法：对象池 + InstancedMesh
  · 预先建 60 个碎块实例（InstancedMesh ✓ 一次 draw call ✓）
  · 碎的时候把实例"激活"✗ 飞 0.6 秒 → 收回池子 ✓
  · 同时最多 60 个碎块 ✗ 再多就复用最老的 ✓
```

## 6. 地貌

| 地貌 | 视觉 | 手感 | 僵尸 |
|---|---|---|---|
| **荒野**（默认） | 草 + 土 + 石头台地 | 正常 | 正常 |
| **冰原** | 浅蓝白，反光 | 移速 **×1.35** ✗ 加减速很慢（惯性）✗ 转身也慢 | 同样打滑 ✗ 会滑过头 ✓ |
| **沼泽** | 深绿 + 水面到脚踝 + 涟漪 | 移速 **×0.6** ✗ 有踩水声 | 移速 ×0.8（它们也陷 ✓） |
| **城区废墟** | 砖地 + 断墙 + 废车 | 正常 | 正常，会从缺口涌进来 |
| **军事区**（以后） | 混凝土 + 铁网 | 正常 | 更强 |

### 6.1 冰面（刹不住车）

```
普通地面：
  松开方向键 → 立刻停（现在是这么做的 ✓）

冰面：
  速度 = 速度 × 0.92 每帧衰减（而不是直接归零 ✗）
  → 松开键还会滑 ~0.6 格才停 ✓
  转向：朝向每秒最多转 240°（普通地面是瞬间 ✓）
  → 急转弯会"甩尾"✓ 很爽 ✗ 也很危险 ✓

★ 为什么只把"摩擦"改小、不改"最大速度"：
  改最大速度的话 → 冰面跑得飞快 ✗ 变成竞速图 ✓
  改摩擦的话 → 起速一样 ✗ 但停不下来 ✓ 这才是"冰"的感觉 ✓
```

### 6.2 沼泽（慢 + 有积水）

```
速度 ×0.6
水面：那一格的顶面抬到"脚踝高度"（0.3 格）✗ 半透明 + 轻微波动 ✓
踩上去：溅一圈涟漪（0.4 秒消失 ✓）+ 踩水声
视觉：水是【贴在地面上的一层】✗ 不是一池子水 ✓
```

### 6.3 地貌怎么分布

```
按【区块】整片生成（32×32 格一个区块）✗ 不零碎 ✓

  区块中心距出生点 < 60 单位 → 荒野（新手区 ✓）
  更远 → 按噪声决定是哪一种（冰原 / 沼泽 / 城区）
  ★ 冰原和沼泽【整片都是】✗ 中间不会夹杂草地 ✓ 好认 ✓

★ 高度和地貌【互相独立但相关】：
  冰原 → 强制低平（h ≤ 1）✗ 冰面开裂的平整感 ✓
  沼泽 → 强制低平（h = 0，全是水 ✓）
  城区 → 允许 1~2 层（楼基 ✓）
  荒野 → 允许 0~5 层（有台地 ✓）
```

## 7. 需要你拍板的 6 件事

| # | 问题 | 我建议 |
|---|---|---|
| 1 | **"超过三格"是指落差 ≥3 还是 ≥4 掉血？** | 建议 **≥3**（落差 2 不疼、3 开始疼），如果觉得太严可以改成 ≥4 |
| 2 | **要不要"跳跃"？** 没有跳跃的话，落差 2 的台子只能绕路或破坏 | 建议**不加跳跃**，落差 2 用"攀爬"（走近按一下上去了 ✓ 慢 0.3 秒 ✓）。跳跃会带出一整套空中控制 ✗ 工作量大 ✓ |
| 3 | **能不能往下挖出坑？** | 建议**只挖 1 层**（挖出坑 ✗ 不能挖穿 ✓），否则地图会被挖出迷宫 ✓ |
| 4 | **一格多大？**（0.62 还是 1.24 世界单位） | 建议 **0.62**（不动现有任何常数 ✓） |
| 5 | **破坏要不要"存库"？** 存了掉线重登墙还是塌的；不存重登就复原 | 建议**存**（这才是"世界被改变"的感觉 ✓ 但要多一张表 ✓） |
| 6 | **树倒了要不要砸到旁边？** | 建议**不要**（第一版先不做 ✓ 以后可以加 ✓ 会砸到自己很烦 ✓） |

## 8. 分阶段实施

> ★ 每一阶段都能【单独上线】✗ 不用等全部做完 ✓

### P0 · 高度（最重要，其他都建在它上面）

```
□ server/terrain.py（新文件）：格子高度 + 材质的纯函数（无状态、可离线测）
□ 客户端 buildChunk 改成按 terrain.py 同样的规则算
□ 地面几何：平面 → 合并的方块几何（只画露出的面）
□ 人物 Y 跟随地面（视觉）+ 落差判定（走不过 3 格墙）
□ 掉落伤害（先客户端算，服务端下一阶段补）
□ 交叉验证测试：客户端 vs 服务端，逐格比高度（照抄现有 dump_props 那套）
```

### P1 · 破坏

```
□ 材质表（硬度和掉落）
□ 挥刀时先判地形
□ 裂纹三段贴图 + 命中抖动
□ 碎裂动画 + 碎块对象池
□ 树 / 房子接入破坏
□ 破坏状态存库（新表 terrain_damage ✗ 只存和生成值不同的格子 ✓）
```

### P2 · 地貌手感

```
□ 冰面惯性（改摩擦，不改最大速度）
□ 沼泽减速 + 水面 + 涟漪
□ 区块地貌分布（整片，不零碎）
□ 僵尸也受地貌影响
```

### P3 · 服务端权威

```
□ 掉落伤害移到服务端判
□ 破坏请求走 intent（防作弊：不能一秒砍 60 下）
□ 反作弊：客户端上报的 y 要和地形高度对得上（差太多就怀疑 ✓）
```

## 9. 风险

| 风险 | 后果 | 应对 |
|---|---|---|
| 客户端/服务端高度算法不一致 | 僵尸穿墙、玩家"悬空" | 第一件事就是写交叉验证测试 ✓ 改任何一边都跑一遍 ✓ |
| 几何量太大 | 手机掉帧 | 只画露出的面 + 合并几何 + 区块剔除 ✓ P0 就压测 ✓ |
| 破坏状态存库太大 | 库暴涨 | 只存"和生成值不同"的格子 ✓ 一格一条 ✓ 平时是空的 ✓ |
| 存档和内存不一致 | 墙"复活"或"消失" | 破坏走现有 intent 队列（和服务端权威一致 ✓） |
| 老存档没有高度 | 全部变平地 | 高度是【算出来的】✗ 不存 ✓ 所以老存档自动就有地形 ✓ |
