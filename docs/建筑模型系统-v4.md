# v4 建筑模型系统：版本化 + 程序化模块

> 目标：建筑外观可以持续调整，但每次调整不破坏已放置建筑。

## 1. 原则

- **模型与功能分离**：`model_id` 只决定外观，功能由 `function_type` 决定；
- **每次调整生成新版本**：`cafe_v1`、`cafe_v2`、`cafe_v3` 同时存在；
- **旧版本不删**：玩家在目录里自由选择要放哪个版本；
- **已放置建筑不自动变样**：放置记录保存 `catalog_id`，不会因为新模型上线而改变；
- **外观可覆盖**：允许改墙色、屋顶色、腰线色、招牌文字，不改结构；
- **碰撞随版本走**：每个版本带自己的碰撞盒；
- **内景随版本走**：每个版本有独立内景配置。

## 2. 数据结构

```text
TOWN_MODELS = {
  cafe_v1: {
    name, type, w, d, h, floors,
    roof: flat|gable|none,
    wall, trim, roofColor, band, awning, sign,
    door, doorW, windows, balcony, columns,
    desc
  },
  cafe_v2: { ... }
}
```

目录表增加：

```text
model_id       -> TOWN_MODELS 的 key
model_version  -> v1/v2/v3
```

服务端只存 `catalog_id`/`model_id`，不存几何数据。

## 4. 调整流程

1. 在预览页确认外观；
2. 新增一个版本，不覆盖旧版本；
3. 写入目录和价格；
4. 玩家在放置目录里选择版本；
5. 旧建筑保持不变。
