## 1. 现在的做法（为什么要改）

```
现在 server/weapons.py 的品阶是这么定的：
   最大品阶 = f(僵尸等级)     ← 硬上限 ✗
   → 45 级僵尸【永远】掉不出 5 阶以上 ✗
   → 1 级僵尸掉 12 阶的概率是【严格 0】✗

用户要的：
   ✓ 1 级也能出 12 阶（极低极低 ✓ 但不是 0 ✓）
   ✓ 等级越高概率越高 ✓
   ✓ 但要有上限（不能练到 200 级就满地 12 阶 ✗）
```

**为什么要这样**（不只是"用户想要"）：
```
① 硬上限 → 玩家一旦到顶，低级怪【完全没价值】✗
   软概率 → 高级玩家回去刷低级怪也有一丝盼头 ✓（极低 ✓ 不破坏平衡 ✓）
② 硬上限 → "我今天运气爆棚"这种故事永远不会发生 ✗
   软概率 → 偶尔出一件越级神装，是这种游戏最爽的瞬间 ✓
③ 硬上限 → 数值策划要按"玩家等级"分段调表 ✗ 段与段之间会跳变 ✗
   软概率 → 一条连续曲线 ✓ 等级推进得平滑 ✓
```

## 2. 新做法：幂律分布 + 等级进度调软

### 2.1 公式（三段，都好算）

```
① 等级进度     x = min(僵尸等级, 击杀者等级 + 20) / 120        （0 ~ 1 ✓ 120 级封顶 ✓）
                 ★ 保留现在的"击杀者+20"限制 ✗ 防止大号带小号刷神装 ✓

② 衰减指数     a = 5.0 − 3.8096 × x^1.2                     （5.0 → 1.1904 ✓）
                 ★ a1 = 1.1904 是【解出来的】✗ 不是拍的 ✓
                   解的目标：满级时 12 阶正好 = 2.0000%（用户定的上限 ✓）

③ 各阶权重     w(t) = (1 / t) ^ a        t = 1..12           （t 是品阶 ✓）
   归一化       P(t) = w(t) / Σw
```

### 2.2 为什么用**幂律**而不是别的

| 方案 | 低等级时 P(12阶) | 问题 |
|---|---|---|
| 硬上限（现在）| **0** ✗ | 用户明确不要 ✗ |
| 高斯（钟形）| e^(−几十) ≈ 10⁻²⁰ ✗ | 尾巴掉太快 → 实际等于 0 ✗ 和硬上限没区别 ✗ |
| **幂律（本方案）** | **0.0004%** ✓ | ✓ 正好"极低但非零"✓ 而且数学上永远是正数 ✓ |
| 线性 | 太高 ✗ | 1 级就 1/12 ✗ 完全没稀有度 ✓ |

> 幂律（也叫长尾分布）就是"**每升一阶，概率除以 tᵃ**"✓
> a 越大尾巴越陡（高阶越罕见 ✓）· a 越小分布越平（高阶越多 ✓）
> **我们就是让 a 随等级变小** ✓ → 一条曲线同时满足用户三个要求 ✓
