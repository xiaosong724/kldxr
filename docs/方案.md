## 1. 技术形态

### 2.1 安全区：末日堡垒

```
分布：每张大地图若干固定堡垒（地图地标，可用来认路）

规则：
  ① 僵尸进不来 —— AI 索敌直接排除堡垒范围 + 物理墙挡住
  ② 禁止一切战斗 —— PvP 与 PvE 都拒（服务器结算时直接拦）
  ③ 不能升级 / 不能突破 / 不能加点 —— 堡垒里不产出任何经验与掉落
  ④ 可以做：回血回灵气、切技能页、换装备、**存取仓库**、当复活点
  ⑤ 不能一直待着 —— 「安逸值」驱赶：
       进堡垒后前 30 秒正常补给
       之后补给速度线性下降到 0（约 5 分钟到 0）
       离开堡垒范围 → 安逸值按 3 倍速度回充
       连续驻留 > 15 分钟 → 提示并逐出（防挂机，可选）
```

> 设计意图：堡垒是**中途补给站**，不是避难所。想变强必须出去。

## 3. 僵尸

**僵尸 = 职业 × 等级**。职业决定行为、属性倾向、掉落；等级决定数值大小。

### 3.1 等级刷新分布

```
以刷新点附近玩家等级 L 为中心：
  ① 50% 概率：Z = L（±1 随机）
  ② 50% 概率：从 0.72^|Z−L| 抽          ← 每远 1 级，概率 ×0.72
  硬下限 Z ≥ 1
  安全上限 Z ≤ L + 40（防开局撞到几百级）
```

L=10 时的实际分布：

| 僵尸等级 | 6 | 8 | 9 | **10** | 11 | 12 | 15 | 20 |
|---|---|---|---|---|---|---|---|---|
| 概率 | 2% | 6% | 12% | **40%** | 12% | 6% | 1.6% | 0.2% |

**组队时**：刷新点确定后，找出该点 **35 单位**内的所有队员 → **随机取一人等级**作为 L（单人即自己）。
→ 三人队带一个高等级，怪有 1/3 概率按他等级刷，低级队友有风险，不能无脑挂机。

### 3.2 数值公式

```
血量 = 75 + 22×Z + 0.62×Z²     ← ★ 系数上调过：防御删掉后玩家打怪变快，这里补偿
攻击 = 8 + 2.5×Z + 0.06×Z²
经验 = 10 + 4×Z + 0.12×Z²
移速 = 1.2 + 0.004×Z（上限 2.6）
```

> 僵尸原本也有"防御"（走同一套减免公式）。玩家侧防御砍掉后，**僵尸防御一并删除**，
> 血量系数上调约 25% 做补偿。**这只是起点，具体数值在 P2 统一校准**。

| 上限 | 值 |
|---|---|
| 客户端同屏渲染 | 40 只 |
| 服务器每区域 | 60 只 |

## 4. 属性系统

### 4.1 点数制

所有概率 / 减免类属性都是**点数**，换算规则：

```
1 点 = 0.5%
```

> 来源：用户给的例子 —— 敌方闪避 10 点 = 5%，我命中 5 点 = 2.5%，对方只剩 **2.5%** 闪避。
> 即对抗关系就是**百分比直接相减**。

### 4.2 属性总表

| 属性 | 类别 | 1点= | 有效值上限 | 对抗 |
|---|---|---|---|---|
| 血量 | 池 | — | 无 | — |
| 灵气 | 池 | — | 无 | **法术消耗资源（蓝条）** |
| 攻击力 | 强度 | — | 无 | 普攻 + `scale: atk` 的技能（**剑修轴**） |
| 法力 | 强度 | — | 无 | `scale: mana` 的技能（**法修轴**） |
| 减伤 | 减免 | 0.5% | **50%** | ← 被穿透抵消 |
| 穿透 | 对抗 | 0.5% | **无** | 抵消减伤 |
| 暴击 | 概率 | 0.5% | **30%** | ← 被免爆抵消 |
| 免爆 | 对抗 | 0.5% | **无** | 抵消暴击 |
| 闪避 | 概率 | 0.5% | **30%** | ← 被命中抵消 |
| 命中 | 对抗 | 0.5% | **无** | 抵消闪避 |
| 爆伤 | 倍率 | — | **+100%**（总 250%） | — |
| 移速 | 倍率 | — | +60% | — |

> **★ 三类属性的「1 点」不是一回事，别混**
> · **对抗类**（减伤/穿透/暴击/免爆/闪避/命中）：1 点 = **0.5%**，成对相减
> · **增益类**（爆伤/移速）：1 点 = **1%** —— 它们没有对抗方，给得大方一点
> · **池/强度类**（血量/灵气/攻击力/法力）：点数直接换数值，
>   具体一点等于多少由**词条模板**定义（见 §7 装备接口），可以按等级缩放

### 4.3 ★ 上限只管「有效值」，投入点数无上限

```
闪避% = 闪避点 × 0.5%                          ← 想加多少加多少
有效闪避% = clamp(闪避% − 命中%, 0, 30%)        ← 只有这里封顶
```

用户举的场景（**这就是设计意图**）：

| 情形 | 闪避点 | 闪避% | 对方命中点 | 有效闪避 |
|---|---|---|---|---|
| 正常 | 60 | 30% | 0 | **30%**（到顶） |
| 被针对 | 60 | 30% | 20（10%） | 20% ↓ |
| 反针对 | **80** | 40% | 20（10%） | **30%**（又满） |
| 继续军备 | 80 | 40% | 60（30%） | 10% ↓ |

→ **堆满了也有意义**，要防对方用对抗属性把你压下去。三组对抗都是这个逻辑。

### 4.4 天赋点

```
每级 +3 点，自由分配，投入无上限
洗点消耗道具
```
100 级 = 300 点 = 150% 的总量，够把两三项堆到远超"有效上限" → 这正是对抗空间。

**★ 防御已被砍掉（别再捡回来）**

```
原设计里"防御"是个独立属性，走 减免 = 防御 / (防御 + 40 + 14×攻击者等级)。
砍掉的三条理由（第三条是决定性的）：
  ① 它和「减伤」本质是同一个东西 —— 都算百分比减伤，两个并存只是理解成本
  ② 它必须靠"攻击者等级"那一项才站得住（防御得写成线性才行），
     等于为了保住一个冗余属性，多背一条带等级项的公式
  ③ 装备一旦继续堆防御，减免照样趋向 100%（防御→∞ 时减免→100%），
     到时候又得给它加个上限 —— 那它就变成减伤了，绕一圈回到原点

"高等级碾压低等级"这件事**不需要防御**：血量和攻击的二次成长已经做到了
  L=50   血 2700 / 攻 360
  L=100  血 8300 / 攻 1110      → 3.07 倍 / 3.08 倍 → 综合优势约 9.6 倍 ✓

结论：**减伤是唯一的减伤属性**（上限 50%，被穿透克制）✓
```

## 5. 战斗结算（服务器权威）

```
有效闪避%  = clamp(闪避点×0.5 − 命中点×0.5, 0, 30)
命中率     = 100% − 有效闪避%
有效暴击%  = clamp(暴击点×0.5 − 免爆点×0.5, 0, 30)
爆伤       = 150% + 爆伤%（总上限 250%）
有效减伤%  = clamp(减伤点×0.5 − 穿透点×0.5, 0, 50)

基础伤害   = 攻击力 × 武器倍率                                 （普攻）
           = 结算属性 × 最终技能倍率（夹 ≤120%，见 §6.5）       （技能）
             结算属性 = (scale == "atk") ? 攻击力 : 法力       ← 字段见 §6.6
最终伤害   = 基础伤害 × (1 − 有效减伤%) × (暴击 ? 爆伤 : 1)
最低伤害   = 基础伤害的 5%（不能被完全免疫）
```

> · **没有"防御减免"了** —— 减伤是唯一的减伤属性 ✓
> · 僵尸打人走**同一套公式**（僵尸没有减伤，所以玩家堆满减伤就能稳吃同级僵尸）

### 5.1 攻速（第 41 轮定稿 —— 先把规矩定死，免得后面加武器时打架）

攻速**拆成两个可感知的量**，都由同一个"攻速倍率"推出来：

```
① 起手（wind-up）：从"决定要打"→"伤害真的落地"的时间   ← 决定手感"轻 / 重"
② 间隔（interval）：两次攻击之间最短的间隔              ← 决定 DPS
```

**为什么必须拆两个**：只缩间隔的话，堆攻速会变成"每刀都很重、但连得飞快"，手感很别扭 ✗；
两段一起缩，才是"又快又轻" ✓（ARPG 通行做法）。

```
攻速倍率 S = clamp(1 + 攻速点 × 0.02, 0.6, 2.2)
   0 点 = 1.00（默认）    50 点 = 2.00（快一倍）    上限 2.2 防"一秒十刀"✗

玩家：起手 = 0.45 / S      间隔 = 0.62 / S        （0.62 就是现在写死的 ATK_CD ✓）
```

**★ 玩家这一期不投入点数，先由【武器类型】决定 S**（用户定的方向）：
**伤害高、范围大的就慢** ✓ 反过来也一样：

| 武器类型 | S | 单次伤害/范围 | 说明 |
|---|---|---|---|
| 匕首 / 爪 | 1.45 | 低伤、小范围 | 贴脸连击 |
| 单手剑 / 刀 | 1.15 | 中伤、中范围 | 基准线附近 |
| 长枪 | 1.00 | 中高伤、**长范围** | 靠距离换 DPS ✓ |
| 双手斧 / 锤 | 0.75 | 高伤、大范围 | 一下是一下 |
| 弓 / 枪械 | 0.85 | 远程 | 单独一套算法（P3） |

> **硬约束（防一把通吃）**：`S × 单次伤害 ≤ 同级基准伤害 × 1.15` ✓
> 也就是"攻速快的武器单次伤害必须低"，两条路线的 DPS 拉平，靠手感/范围做区分 ✓

**★ 僵尸也有攻速**（用户反馈："贴近了就算直接打，应该要慢一点点"）：
僵尸**没有连击**，只有"起手 → 咬 → 收招"：

```
贴到身前 → 蓄力 WINDUP 秒（客户端从这一刻开始抬爪 ✓）→ 咬出去 → 收招 RECOVER 0.35 秒
下一次最短间隔 = WINDUP + RECOVER

职业的 WINDUP（§3.3 的行为特性落到数字）：
   学生 / 外卖        0.30   弱/快，一涌而上 ✓
   白领 / 医生 / 程序员 0.45   普通杂兵 ✓
   保安              0.55   端着架子，慢半拍 ✓
   工人 / 健身教练     0.70   高血高攻就得慢 ✓
```

> ★ **起手期间被打断怎么办**：一期**不做打断**（僵尸蓄力完一定咬出去）✓
> 理由：打断要引入"硬直"这个概念，和 §5 的减伤/格挡会互相纠缠；等 P4 的 PvP 真需要了再谈 ✓

### 6.2 ★ 倍率带的硬约束（"不能一下秒同级"）

```
同级玩家  血/法力（= 倍率的分母）：
  L=10    血 380     法力 160    比 2.38
  L=50    血 2700    法力 1000   比 2.70
  L=100   血 8300    法力 2950   比 2.81
  L=200   血 28500   法力 9850   比 2.89
  → 比值随等级从 2.07 涨到 3.0（血和法力都是 L²，但常数项不同）
    算账时取 2.8 当代表值 —— 低等级会更"疼"一点，这是有意的

非暴击打掉同级多少血 = 最终倍率 ÷ 该等级的血/法力比
```

| 最终倍率 | L=10 时 | L=100 时 | 评价 |
|---|---|---|---|
| 400% | 168% | 142% | 一下秒 ✗ |
| 250% | 105% | 89% | 低等级秒、高等级两下 |
| **120%** | **50%** | **43%** | **两~三下 ✓ 定稿上限** |
| 80% | 34% | 28% | 三~四下 |

→ **整条数值带定在 12% ~ 120%**
→ 暴击：120% × 2.5 = 300% 法力 → L=100 时打掉 107%、L=10 时 126%。
  **极限暴击（神品满 roll + 暴击满 + 爆伤满 + 目标零减伤）确实能一下秒同级** ——
  这是"全砸输出"该有的回报；正常有减伤就秒不掉 ✓

### 6.4 区间内 roll（越高越难出）

```

```

### 6.5 技能等级与升阶（★ 倍率最终硬夹 120%）

```
最终倍率 = 品阶倍率 × (1 + 技能等级 × 0.03)   → 再硬夹到 ≤ 120%
灵气消耗 = 基础消耗 × (1 + 技能等级 × 0.06)
技能等级上限：20
升阶：同名低阶 ×3 + 材料 → 高一阶（重复掉落不浪费）
来源：技能书掉落 / 突破解锁
```

**★ 为什么要夹（这条也改过，原因记下来）**

```
若按"倍率 × (1 + 等级 × 0.08)"算，技能等级 20 就是 ×2.6：
  120% × 2.6 = 312% 法力 ÷ 2.8 = 111% 血 → 一下秒同级 ✗
  （§6.2 推的"120% 不秒人"只算了技能等级 0 的情况，自己打自己脸）

改成"每级 +3%，最终倍率硬夹 120%"：
  12%~120% 就是绝对上限，任何来源叠完都超不过 ✓
  技能等级的作用变成"把低品阶技能推到它的天花板"，而不是突破天花板 ✓
```

### 7.5 伤害怎么算（固有属性 × 武器，两条成长线都要有感觉）

```
玩家攻击力 = 固有攻击 × 武器伤害系数 + 武器平伤 + 词条加成
    固有攻击 = 10 + 3L + 0.08L²            （§4.5，随等级长 ✓）
    武器平伤 = 同阶基准值 × (1 + 0.06 × 物品等级)
    词条加成 = §7.2 那套（pct 乘、flat 加 ✓）
单次伤害 = 玩家攻击力 × 随机(0.9 ~ 1.1) × 暴击(§5)
```

## 13. 性能架构（50 人目标）

**三条线程，各管一摊（没有锁、没有 await、没有磁盘 IO 混在里面）**：

```

存档线程 = 只写数据库（攒批落盘）
★ 没有锁 —— 因为世界状态只有 tick 线程碰 ✓ 别的线程只往队列里丢东西 ✓
★ World._to_net() 每个 tick 只打包一次（不是每个玩家一次）✓
★ tick 预算：目标 tickMs < 2ms（实测 0.1~0.5ms，见 /api/health 的 world.tickMs ✓）
```

**50 人怎么撑**：

### 13.1 ★ 客户端渲染实测（第 44 轮补 —— 这一节以前只有原则，没有数字）

**方法**：无头 Chrome + CDP 注入探针，数 `renderer.info.render.calls`、
给 `frame()` / 各构建函数直接计时、按"关掉某一类物体"做归因。

> ⚠️ **读这些数字要注意**：无头 Chrome 用的是**软件渲染（SwiftShader）**，
> 所以【绝对毫秒数偏悲观、且波动很大】✗ 不能直接外推到真机 ✗
> 但两类数字是**硬件无关、可信**的：
> · **draw call 数**（就是它决定手机能不能跑）
> · **JS 函数耗时**（纯 CPU 计时，不受合成器影响）
> ★ 这个 session 里我因为忽略这一点误判过三次（"渲染之外 17ms"、"33ms 顿挫是地面重建"），
>   教训：**先量函数耗时，再谈优化**；别拿软件渲染的帧率当结论 ✗

**优化前后（40 只僵尸，同一台机器、同一个探针）**

| 最差帧 | 33.4ms（掉帧） | **16.8ms** | 不再掉帧 |
| 空场景 | 84 / 0.86ms | 38 / 0.23ms | ↓ 55% / ↓ 73% |
| 一只僵尸的网格数 | 21 | **5** | ↓ 76% |

**做了什么（全部画质零变化）**

   ★ 共享材质之后，死亡淡出（改 material.opacity）必须先克隆那一只的 ✗ 已处理

   ★ 灯数必须封顶：实测 40 盏 = 4 倍开销 ✗ / 2 盏 = 1.2 倍 ✓
