## 1. 核心思路：**一套数据，三个出口**

```
              ┌───────────────┐
              │ 公告数据(JSON) │  ← 我写 / 管理页也能改
              └───────┬───────┘
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   游戏内弹窗     管理页预览      群里的 PNG 海报
  （HTML 渲染）  （同一个渲染器） （poster_news.js）
```

★ 关键：**渲染器只有一份**（`web/lib/annrender.js`），游戏里、管理页预览、出图脚本全用它 ✓
→ 以后"游戏里看到的"和"发群的图"永远长得一样 ✗ 不会各写一套跑偏 ✓

## 3. 数据模型

```sql
CREATE TABLE announcements (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    ver          TEXT,                 -- 'v1.2'（可空）
    title        TEXT NOT NULL,        -- 更 新 公 告
    date         TEXT,                 -- 2026-10-19
    headline     TEXT,                 -- 皮肤系统上线
    badge        TEXT,                 -- 绿色胶囊（刷新即可生效）
    foot         TEXT,                 -- 底部小字（允许 <b> <br>）
    items_json   TEXT NOT NULL,        -- [{tag, t, b:[...]}]
    status       TEXT NOT NULL DEFAULT 'draft',  -- draft | live | retracted
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER,
    published_at INTEGER
);
ALTER TABLE roles ADD COLUMN announce_seen INTEGER NOT NULL DEFAULT 0;
```

- `items_json` 和 `poster_news.json` 的 `items` **完全同构** ✓ 我的出图脚本可以原样吃它 ✓
- 已读判定：`live` 里 id 最大的那条 vs `roles.announce_seen`

## 5. 管理页：**单独一个导航页**（用户要求）

- 地址：`/admin/announce`（新页面 `web/admin-ann.html`）
- 后台管理首页右上角加一个入口：「📢 公告管理 →」
- 页面上三块：

```
┌ 公告管理 ────────────────────────── 返回世界管理 ┐
│ [ + 新建公告 ]  状态: [全部▾]                     │
├ 列表 ─────────────────────────────────────────────┤
│ #8 v1.3 皮肤系统上线  2026-10-19  ● 已发布  [编辑]│
│ #7 v1.2 武器机制      2026-10-18  ○ 草稿    [发布]│
│ #6 v1.1 交易行        2026-10-17  ⊘ 已撤回  [复制]│
├ 编辑区（点开才出现）─────────────────────────────┤
│ 左：表单                       右：实时预览        │
│  标题/日期/一句话/胶囊/底部小字   （同一个渲染器）   │
│  卡片列表：分类▾ 标题 条目(每行一条) ＋ / －        │
│  [ 存草稿 ] [ 发布 ] [ 另存为新公告 ] [ 删除 ]      │
└───────────────────────────────────────────────────┘
```

| 动作 | 行为 |
|---|---|
| 存草稿 | `status='draft'`（不弹）|
| 发布 | `status='live'`，`published_at` 记时间 → **所有 seen < id 的玩家下次登录弹** |
| 撤回 | `status='retracted'`（留档、不再弹；已看过的人无感）|
| 编辑（已发布的）| 改内容但**不换 id** → 只影响**还没看过**的人 ✓ 看过的人不会再被弹 |
| 另存为新公告 | INSERT 新 id + live → **所有人都会再看一次** ✓（想强制重发用这个）|
| 删除 | 只允许删草稿 ✓（已发布的只能撤回 ✗ 留档）|

## 6. 游戏内弹窗

```
┌─────────────────────────────────────┐
│  更 新 公 告                 ⏱ 15    │   ← 右上倒计时圈
│  2026-10-19 · 皮肤系统上线            │
│  ┌─────────────────────────────────┐ │
│  │ 01 [皮肤]  40 套皮肤            │ │   ← 照海报样式
│  │   ▪ 男女各 20，骨架各自不同      │ │      可滚动
│  │ 02 [掉落]  打怪 1% 掉皮肤卡      │ │
│  │   ▪ …                           │ │
│  └─────────────────────────────────┘ │
│              [ 知道了 ]              │
└─────────────────────────────────────┘
```

| 规则 | 行为 |
|---|---|
| 出现时机 | 进世界握手 `welcome` 带 `ann` 时（只在有未读 ✓ 绝不在游戏中途弹 ✓）|
| 自动关 | **15 秒**，右上角倒计时圈（15→0）|
| 手动关 | 点遮罩 / 点知道了 / 点 × / **面板内滑动（滚轮·touchmove·拖动）** / 键盘任意键 |
| 已读上报 | **关闭那一刻**才发 `annread{id}` ✓（中途掉线不算看过 ✓ 下次还弹）|
| 重复弹 | 不会：seen 写库 ✓ 换设备也不重复 ✓ |
| 尺寸 | `max-width:min(560px,92vw)` / `max-height:86vh` / 卡片区自己滚 |

## 7. 接口 / 协议

| 接口 | 用途 |
|---|---|
| `GET /api/announce/latest` | 公开读最新 live（管理页预览也用它）|
| `GET /api/admin/announce?all=1` | 历史列表（含草稿/撤回）|
| `POST /api/admin/announce` | 新建（草稿或直接发布）|
| `PUT /api/admin/announce/{id}` | 改内容 / 改状态 |
| `DELETE /api/admin/announce/{id}` | 只允许草稿 |
| WS `welcome.ann` | 玩家端拿到未读公告 |
| WS `annread {id}` | 标记已读（只增不减 ✓ 服务端校验 id ≤ 最新 ✓）|

## 8. 安全 / 边界

| 场景 | 处理 |
|---|---|
| 内容注入 | 只允许 `<b> <br>` ✗ 其余转义（服务端过滤 + 渲染器再转义一次 ✓）|
| 玩家伪造 annread 超大 id | 服务端 `min(id, 最新)` ✓ 不能把以后的公告都跳过 |
| 连发两条都没看 | 只弹最新，已读直接记到最新 ✓ |
| 公告太长 | 卡片区滚动 ✓ 面板不超 86vh ✓ |
| 手机竖屏 | 单列卡片（海报是双列 ✗ 手机上双列太挤 ✓ 用媒体查询切）|
| 老玩家 seen=0 | 第一次登录见到当前最新公告 ✓（不想打扰就先别发布 ✓）|
| 公告里有 `</div>` 之类 | 转义 ✓ 不会破版 |
| 游戏内渲染失败 | try/catch → 静默不弹 ✗ 绝不挡住进游戏 ✓ |
