## 0. 一句话结论

```
MC 的水/岩浆本质是【同一套"流体 + 等级"系统】✗ 只是参数不同 ✓
  水：8 级（0 = 源头 ✗ 1~7 = 流出来的）✗ 先往下 ✗ 下不去才横着铺 ✓
  岩浆：同样 8 级 ✗ 但只铺 2~4 格（比水短）✗ 慢很多 ✗ 会烫死人 ✓

★ 但【照抄 MC 会踩三个坑】✗ 这个项目有三个完全不同的约束：
  ① 手机 + 30Hz tick ✗ 不能像 MC 那样全世界都在流动 ✓
  ② 地形是两边确定性生成的 ✗ 流体是【会变的】✗ 必须服务端权威 ✓
  ③ 这是末日修仙 ✗ 不能只是"水"和"岩浆"✗ 要有修仙味 ✓ → §6
```

## 1. MC 是怎么做的（参考）

| 项 | 水 | 岩浆 |
|---|---|---|
| 等级 | 8 级（0 源头 / 1~7 流动） | 同样 8 级 |
| 铺多远 | **7 格**（等级越大越浅） | **4 格**（主世界 ✗ 下界 8 格） |
| 流动方向 | **先往下**✗ 下面堵住才横着流 ✓ | 同样 |
| 更新频率 | 每 5 tick 一次 | 每 30 tick 一次（**慢 6 倍**） |
| 碰到人 | 减速 / 能游泳 / 会淹（憋气 15 秒） | **4 颗心伤害 + 着火** |
| 水+岩浆 | — | 流动的岩浆碰水 → **圆石** ✗ 源头碰水 → **黑曜石** ✓ |
| 源头 | 2×2 或相邻两个源头 → 生成新源头 | 只有桶能放 |

★ 三条最有价值的机制（值得抄）：

```
① 【源头 / 流动】分开 ✗ 流动的水会干 ✗ 源头无限 ✓
   → 玩家可以"引一条水渠"✗ 但拦断源头就没了 ✓ 很好玩 ✓
② 【先下后横】✗ 所以往坑里倒水会填满 ✓ 在平地上会摊成一片 ✓
   → 这是"流体的直觉"✗ 玩家不用学就会 ✓
③ 【水 + 岩浆 = 石头】✗ 这是 MC 最聪明的设计之一 ✓
   → 它把"危险"变成了"工具"✗ 玩家会主动去引水造路 ✓
```

## 2. 三条不能照抄的地方（这个项目的约束）

```
① 性能：MC 只模拟【加载中的区块】✗ 而且有专门的流体线程 ✓
   这边是【一个 tick 线程】✗ 还要跑僵尸 / 交易所 / 掉落 ✓
   → 必须【有预算地模拟】✗ 见 §4 ✓
   → 而且只有玩家附近才模拟（远处的流体"冻结"✓ 反正看不见 ✓）

② 一致性：地形是两边各算一遍（确定性 ✓）
   但流体【会变】✗ 不能两边各算 ✓ → 必须【服务端说了算】✓
   → 客户端只负责画 ✗ 收到什么画什么 ✓
   ★ 这是本项目第一个"服务端权威的世界状态"✗ 要谨慎 ✓
   ★ 好在地形方案里已经有 terrain_damage 那张表的做法可以照抄 ✓

③ 存档：流体状态要存（不然重启后水就没了 ✗ 或者倒流 ✓）
   → 只存【和生成值不同】的格子（照抄 terrain_damage ✓ 见 §5 ✓）
```

## 3. 玩法设计（修仙味）

### 3.1 两种流体 × 三种形态

| 名字 | 是什么 | 出现在哪 | 碰到的后果 |
|---|---|---|---|
| **清水**（山泉/湖） | 正常的水 | 湖泊 / 河流 / 城区积水 | 减速 ×0.55 ✗ 能游 ✗ **能灭火** ✓ |
| **灵泉**（稀有） | 发淡蓝光的水 | 少数山洞 / 山顶 | 泡在里面**回灵气**（每秒 +2）✗ 僵尸不进来 ✓ |
| **污水** | 沼泽水（绿黑 ✗ 有气泡） | 沼泽 | 减速 ×0.45 ✗ **每秒 −1 血**（腐蚀 ✓ 不会死 ✓） |
| **地火**（岩浆） | 橙红发光 ✗ 冒烟 | 地裂 / 火山口 / 废弃工厂熔炉 | **烫伤 + 灼烧（持续掉血）** |

★ 为什么不直接叫"水和岩浆"：
  这是修仙游戏 ✗ "灵泉"和"地火"能直接接上【炼丹 / 炼器 / 灵气】那几套系统 ✓
  而且以后加"火系功法"时，"地火"是个现成的素材 ✓

### 3.2 关键互动（这是最好玩的部分）

```
水 + 地火 → 黑曜石 / 石头
  ★ 和 MC 一样的逻辑 ✗ 但作用更大：
    玩家可以用【引水】把一片地火封成路 ✗ 这是解谜式的开路 ✓
    反过来 ✗ 地火也能被水"浇灭"成石头 ✗ 危险区变成安全区 ✓

水流推人
  ★ 横着流的水会把你往水流方向推（±0.4 速度）✗
    可以用来做"水滑梯"✗ 也会把你推进地火 ✓ 很刺激 ✓

地火杀僵尸
  ★ 僵尸不会躲地火 ✗ 走进去就烧死 ✓
    → 玩家会主动"引怪入火"✗ 这是很爽的战术 ✓

水下憋气
  ★ 清水里憋气 12 秒（比 MC 短 ✗ 手机玩家没耐心 ✓）
    憋不住就掉血（每秒 5% 最大生命 ✓ 统一用百分比 ✗ 见 §4.4 ✓）

污水腐蚀 / 灵泉回复
  ★ 这两个是【地貌的奖励和惩罚】✗ 让玩家愿意绕路或特意去找 ✓
```

### 3.3 和现有地貌的关系

```
沼泽（已有）：整片换成【污水】✗ 深度 1 格（水到脚踝 ✓ 方案 §6.2 写过的）
冰原（已有）：不铺水 ✗ 但冰下面可以埋【地火裂隙】✗ 踩碎冰会掉下去 ✓（很坏 ✗ 但很好玩 ✓）
城区（已有）：地下管道积水 / 工厂熔炉（地火）✓
荒野（已有）：偶尔一个小湖 + 灵泉（很稀有 ✗ 约 1/40 的区块 ✓）
新增地貌：**地裂**（焦土 + 地火）✓ 越靠外圈越多 ✓
```

## 4. 技术方案

### 4.1 数据

```
每格多两个字段（和现有的 h / mat / slope 并列 ✓）：

   fk   流体种类：0 = 没有 / 1 = 清水 / 2 = 污水 / 3 = 灵泉 / 4 = 地火
   fl   流体等级：0 = 源头 / 1~7 = 流出来的（数字越大越浅 ✓）

★ 流体【不参与地形生成】✗ 生成时只决定"哪里有源头"✓
  → 所以 h / mat / slope 还是纯函数（确定性 ✓ 两边一致 ✓）
  → 只有 fk / fl 是【会变的状态】✗ 存库 ✓ 服务端权威 ✓

★ 水位高度 = (1 − fl/8) 格   （源头满格 ✗ fl=7 只剩 1/8 格 ✓ 和 MC 一样 ✓）
```

### 4.2 流动规则（抄 MC ✗ 但简化）

```
每个"活跃格"每次更新：

① 先看下面（h 更低的邻居）
   如果下面能流 → 往下流 ✗ 等级清零（继续是满的源头）✓
   ★ 这一步优先 ✗ 所以水总是先填坑 ✓

② 下面堵住了 → 横着流
   往 4 个方向：能流的方向 = 等级 + 1（越流越细 ✓）
   等级 ≥ 7 → 不再流（走不动了 ✓）
   ★ 地火只流到 3（比水短一半 ✓ 危险区不会太大 ✓）

③ 平衡判定（什么时候"停"）
   如果这一格的等级 ≥ 它所有来源里最小的那个 + 1 → 它会变浅
   如果变浅到 0 → 消失 ✓
   ★ 这样"把源头堵掉之后水会退"✗ 自动 ✓ 不用特判 ✓
```

### 4.3 性能：这一节是全篇最重要的

```
★ 绝对不能用"每 tick 扫全图"✗ 4096 格 × 4 个方向 = 每秒 50 万次 ✓ 手机直接死 ✓

做法：【活跃集合】+ 预算

   维护一个 active 集合（格子坐标）
   只有这些格子会被处理：
     · 玩家破坏/放置了格子 → 它和它的 4 个邻居进集合 ✓
     · 一个格子的等级变了 → 它的 4 个邻居进集合 ✓
     · 玩家走近一片水 → 那片水进集合（"解冻"✗ 让它重新平衡一次 ✓）

   每 tick 最多处理 N 个（N = 120 试）✗ 处理不完就留到下 tick ✓
   一个格子都不活跃时 → 这个系统【完全不花钱】✓

★ 玩家走远之后：那片水【不再更新】✗ 状态就停在那儿 ✓
  （反正是看不见的地方 ✗ 玩家回来时它再平衡一次 ✓ 观感完全一样 ✓）
  → 这就是"远处的水冻结"✗ 但不会有人发现 ✓

★ 预算实测目标：满负荷 120 格/帧 ≈ 0.3ms ✓
   （和交易所的 4000 行扫一次是同一个量级 ✓）
```

### 4.4 伤害（和现有的掉落伤害统一口径）

```
地火烫伤        接触时每 0.5 秒 1 次 ✗ 每次 max(5, 2% 最大生命) ✓
灼烧（离开之后）  持续 3 秒 ✗ 每秒 max(3, 1% 最大生命) ✓ 泡水立刻灭 ✓
污水腐蚀        每秒 max(3, 1% 最大生命) ✓
憋气             12 秒之后每秒 max(5, 2% 最大生命) ✓
灵泉            每秒 +2 灵气（回蓝 ✓ 不回血 ✓）

★ 掉落伤害用户定了"纯固定 5 点"✗ 这里为什么又用百分比：
  掉落是【一次性的】✗ 疼一下就完了 ✓ 固定值够用 ✓
  流体是【持续的】✗ 固定 5 点/秒在 60 级（3580 血）等于没有 ✓
  → 持续伤害必须按百分比 ✗ 否则高级号可以泡在地火里洗澡 ✓
  ★ 这一条要提醒用户拍板（见 §8）✓
```

### 4.5 渲染

```
流体不是方块 ✗ 是【贴着地面的半透明层】✓

清水  青蓝色 ✗ 透明度 0.55 ✗ 表面轻微起伏（±0.02 格 ✓ 用时间 sin 算区域偏移）
灵泉  同色但带淡青光 ✗ 半透明 0.45 ✗ 会往上报"这里有东西"（小地图上标一个点 ✓）
污水  墨绿偏黑 ✗ 透明度 0.75 ✗ 表面偶尔冒一个气泡
地火  橙红 ✗ **不透明** ✗ 自发光（不受光照 ✗ 一直亮 ✓）✗ 表面慢慢流动 ✓
      ★ 地火周围要有【光】✗ 否则在夜里看不出来 ✓（现在没有点光源系统 ✗ P1 先做"地面橙光贴片"✓）

★ 水面高度 = 该格顶面 + (1 − fl/8) × LEVEL_H
  → 所以水浅的地方能看见地面 ✓ 深的地方是整块 ✓ 和 MC 的观感一致 ✓

★ 和地形的 z-fighting：
  水面抬高 0.005 世界单位 ✗ 不要完全贴合 ✓（贴合会闪 ✓ 这个坑所有 3D 项目都踩过 ✓）
```

## 5. 存档（照抄 terrain_damage 的做法）

```
新表 fluid_cells：
   x, z, fk, fl, updated_ms

★ 只存【和生成值不同】的格子 ✗ 生成出来的湖不用存（种子能算出来 ✓）
★ 玩家把水引到别处 → 多一行 ✓ 把水堵回去 → 删掉那行 ✓ 表会自己变小 ✓
★ 上限 2 万行（超过就丢最老的 ✗ 反正是远处的 ✓）
★ 重启后：先按种子生成"天然的水"✗ 再把表里的覆盖上去 ✓
```

## 6. 为什么这样设计（而不是更简单/更复杂的版本）

```
反例 A：只做【静态水池】✗ 不能流动
  → 破坏墙不会灌水 ✗ "引水浇地火"这个核心玩法就没了 ✓
  → 省事 ✗ 但少了最有趣的一半 ✓

反例 B：照抄 MC 全世界流动
  → 手机跑不动（MC 是 Java + 专用线程 ✗ 这边只有 JS + 一个 tick ✓）
  → 而且一致性会崩（两边各算流体 ✗ 差一点就"你那有水我这儿没有"✓）

反例 C：做成"魔法液体"（和地形无关 ✗ 自己一套规则）
  → 玩家学不会（"为什么水能穿墙"✗）
  → 而且没法复用现有的高度/破坏系统 ✓
  → 现在这套是【贴在地形上】的 ✗ 破坏墙 → 水自然灌进来 ✓ 不用写特判 ✓
```

## 7. 分阶段

> 每个阶段都能单独上线 ✓

### F0 · 静水（只生成，不流动）

```
□ terrain.py 加 fluid_of(gx,gz)：按地貌决定哪里有水/地火（纯函数 ✓）
□ 客户端：流体表面渲染（透明度 / 水位高度 / 地火自发光）
□ 玩家在水里减速 / 地火烫伤 / 污水腐蚀
□ 存档：天然流体不用存（种子算得出来 ✓）
★ 完成标志：能走进湖里、能看到地火在发光、踩地火掉血
★ 这一阶段【零 tick 开销】✗ 因为不流动 ✓
```

### F1 · 流动（核心）

```
□ 活跃集合 + 预算（§4.3）✗ 这条决定成败 ✓
□ 流动规则（先下后横 ✓）
□ 水 + 地火 = 石头（就地凝固 ✓）
□ fluid_cells 表 + 存读
□ 客户端：收到流体更新就改那片瓦片（只重建受影响的瓦片 ✓）
□ 引水推人（可选 ✗ 见待拍板 ✓）
```

### F2 · 修仙味

```
□ 灵泉（回灵气）
□ 地火用来炼丹（等炼丹系统 ✓）
□ 冰原下面埋地火裂隙
□ 流体声（水声 / 地火咕嘟声 ✓ 按距离淡入 ✓）
```

## 9. 风险

| 风险 | 后果 | 应对 |
|---|---|---|
| 流体模拟吃掉 tick | 全世界卡顿 | 活跃集合 + 预算 120/帧 ✗ P1 第一件事就是压测 ✓ |
| 流体状态两边不一致 | "你那有水我这儿没有" | 服务端权威 ✗ 客户端只画 ✓ 不自己算 ✓ |
| 水面和地形 z-fighting | 水面闪烁 | 抬高 0.005 ✗ 见 §4.5 ✓ |
| 流体存档涨太大 | 库变大 | 只存和生成值不同的格 + 2 万行上限 ✓ |
| 水流到未加载区域 | 那一片永远不更新 | 玩家走近时"解冻"重算一次 ✓ 见 §4.3 ✓ |
| 地火把玩家困住 | 掉进去出不来 | 地火只铺 3 格（水是 7 格 ✗ 地火危险区小一半 ✓）+ 凝固成石头能踩着出来 ✓ |
