## 1. 这一轮做完了什么

### 1.1 v4 数据底座（schema v22）

- 新增 8 张表：`towns` / `town_perms` / `town_catalog` / `town_objects` / `town_ground` /
  `town_ledger` / `town_payments` / `town_audit`。
- `server/towns.py`：7 项权限、档位与费用、50 格间距校验、建镇 / 冻结 / 恢复 / 解散、
  80/20 账本、目录种子（`seed_catalog()`）。
- 启动自动建系统主城「新手镇」。

### 1.2 权限与小镇面板

- 权限位：`MOVE=1 INTERACT=2 TRADE=4 PERM=8 REMOVE=16 PRICE=32 TELEPORT=64`，
  `P_ALL=127`，`P_VISITOR=70`。
- 客户端「小镇」面板：建镇（名字 / 档位 / 坐标 / 费用）、查看到期与日费、
  解散、冻结恢复、按玩家 ID 勾 7 项权限、竖屏适配。

### 1.3 建筑模型系统（这一轮的大头）

- `web/core/town_models.js`：**23 个模型**（22 栋建筑 + 传送阵），每栋一个独立版本 spec，
  颜色 / 招牌文字 / 层数 / 门朝向都在 spec 里，同一套 `buildTownModel()` 分发。
- 拆成 5 个文件避免单文件过大：
  `town_shops2.js`（咖啡 / 拉面 / 面包 / 杂货 / 花店）、
  `town_shops3.js`（仓库 / 铁匠 / 药铺 / 邮局 / 书店 / 酒屋）、
  `town_shops4.js`（公寓 / 旅店 / 澡堂 / 茶馆 / 甜品 / 警亭）、
  `town_villas.js`（别墅，真两层 + 楼梯 + 阳台 + 卫浴）、
  `town_hall.js`（市政厅 + 传送阵）。
- `town_props.js`：29 种户外道具（树 / 路灯 / 长椅 / 花坛 / 邮筒 / 自动售货机 / 摊位……）。
- `town_veg.js`：叶子 / 花 / 茎的复用小工具。
- 预览页支持：颜色拾取、招牌文字、剖切、部件清单（中文名）、家具清单、点击拾取跳过隐藏物件。

### 1.4 家具目录与默认布局

- 家具目录 34 个 catalog id（32 个独立模型，`chair`→`chair_wood`、`table`→`dining_table`、
  `bench`→`prop_bench` 是别名），全部**可复用到任意建筑**。
- `server/town_layouts.py`：22 套布局，按楼层（`y:` 支持二层）给出每个家具的 catalog id + 相对坐标 + 朝向。
- **放置建筑时按布局自动生成家具子对象**（`parent_id` = 建筑对象 id，随建筑一起移动 / 删除 / 退款）。
- 家具与建筑一样可移动、可移除、可标价；建筑自带默认家具**不额外收费**。

### 1.5 放置 / 移动 / 移除

- `server/town_objects.py`：`place_object` / `place_building` / `move_object` / `remove_object` /
  `replace_with_model` / `world_boxes` / `inside_town` / `overlaps_existing` / `nearby`。
- **真实碰撞**：每个 catalog 都有 `collision_json`（相对 AABB 列表），放置与移动都做
  「盒内 + 不重叠 + 在小镇边界内」三重校验，旋转后按 `_rot_box` 重算。
- `web/platform/place.js`：放置面板、幽灵预览、`R` 旋转、`Esc` 取消、落点红色/绿色提示。
- 协议：C2S `place` / `place_building` / `move_object` / `remove_object` / `town_objects`；

## 3. 关键约定（改代码前先记住）

- **地址**：放置物一律 `obj<row id>`（如 `obj334`）；静态老对象保留旧 id（`villa_1`、店铺 id）。
- **尺度**：1 格 = **0.62m**。主城 500×500。档位 30/50/80/100 格 → 18.6 / 31 / 49.6 / 62 m。
- **费用**：`fee_for(tier) = 5,000,000 × (tier/30)²`，取整到万 →
  5,000,000 / 13,890,000 / 35,560,000 / 55,560,000。
- **物件上限**：100 / 250 / 600 / 1000（对应四个档）。
- **间距**：两个小镇之间至少 50 格 = 31m。安全区 = 小镇矩形外扩 2 格 = 1.24m。
- **`owner_id = 0` 表示公共**（放置建筑默认 0）。静态建筑的"房主"语义在放置建筑上是"公开"。
- **交互半径**：商店 3.2m，座椅 `SEAT_USE_R = 2.3`，放置的房子 / 冰箱 6.0m。
- **家具归属**：建筑放置时按 `LAYOUTS` 生成子对象，`parent_id` 指向建筑；
  移动建筑带家具一起走，删除建筑级联删家具。
- **版本化**：任何视觉改动 = 新模型版本（`..._v2`），旧版本保留可放置，不许原地改老 spec。
- **分层**：`web/core/*.js` 不许碰 DOM / `window`；平台层写 `TOWN_OBJECTS_CACHE`，核心层读它。

### WebSocket 冒烟（等回复要读够消息）

30Hz 的 `world` 快照会把回复淹没，**读 120 条再断言**，别只读 20 条：

```python
import asyncio, json, urllib.request, websockets

def post(path, data):
    req = urllib.request.Request('http://127.0.0.1:8899' + path,
                                 data=json.dumps(data).encode(),
                                 headers={'Content-Type': 'application/json'})
    return json.load(urllib.request.urlopen(req))

tok = post('/api/login', {'username': '...', 'password': '...'})['token']

async def main():
    async with websockets.connect('ws://127.0.0.1:8900/ws') as ws:
        await ws.send(json.dumps({'t': 'hello', 'd': {'token': tok}}))
        await ws.send(json.dumps({'t': 'sit', 'd': {'id': 'obj334'}}))
        for _ in range(120):
            m = json.loads(await ws.recv())
            if m['t'] in ('seated', 'error'):
                print(m)
                break
asyncio.run(main())
```

## 6. 已知坑（都是真踩过的）

1. **绝对不要用 PowerShell 改 UTF-8 中文文件。**
   `Get-Content` / `Set-Content` 会按 ANSI 往返，把中文变乱码；上一轮它把
   `preview_models.html` 写坏成 `?/label>`，整页白屏。
   → 只用 `write` / `edit` 工具，或 Python `io.open(..., encoding='utf-8', newline='\n')`。

2. **改完 `server/*.py` 必须重启进程。**
   曾经出现 `world.py` 的 mtime（7:12）比进程启动时间（7:09）还新，代码改了没生效，
   白查两小时。重启后用 `Get-Process python | Select Id,StartTime` 对一下时间。

3. **`server/net.py` 里冰箱逻辑有两份**（约 339 行与 545 行，两段
   `if t in ('fridge_open','fridge_put','fridge_take')`）。
   任何"动态对象 + 冰箱"的改动**两处都要改**，只改一处会出现「主城能用、放置建筑不能用」。
   教训来自：两处都去查静态 `houses` 表 → 放置建筑返回 `NO_HOUSE`。

4. **家具部件必须显式注册。**
   `tmPiece` / `tmBeginPiece` / `tmBind` / `tmEndPiece` / `tmCollectFurniture`；
   按名字猜的老规则会漏掉子部件（椅子丢腿、植物丢叶子、床宽成 2.07）。
   自定义 builder（别墅 / 市政厅）**必须自己在末尾调 `tmCollectFurniture(g)`**，否则家具清单为 0。

5. **家具挂在 `dg` / `wg` 子组里时，要注册到模型根。**
   `tmRoot()` 向上走到模型根；`tmCollectFurniture` 递归扫描。

6. **`p.seat` 可能是字符串 `obj334`。**
   有两处 `int(getattr(p,'seat',-1))` 会直接崩，比较时一律按字符串安全处理。

7. **`core/` 层不许出现 `window` / DOM。**
   `web/core/town.js` 曾读 `window.MY_OBJECTS` 被闸门抓住，改成读 `TOWN_OBJECTS_CACHE`。

8. **`server/protocol.py` 的 `S2C` 字典曾经整个不存在**，`describe()` 引用它就抛。
   加新 S2C 消息时确认表里有。

9. **`bed` / `sofa` 是 `Group` 不是 `Mesh`。**
   只遍历 `isMesh` 的收集器会漏掉它们。

10. **注册流程有用户名正则**：`^[0-9A-Za-z_\u4e00-\u9fa5-]{2,10}$`，
    不合规返回 400（不是 500），别误判成服务端挂了。

11. **管理接口用 `X-Admin` 头**（密码 `xiuxian-admin`），不是 `X-Token`。

12. **金币以内存为准。** 直接改 `roles.gold` 要重启服务，否则登录读到的还是旧值。

13. **测试账号**：`z####` / `h####` / `f####` / `[a-z][a-z0-9]{7}` 是历次调试留下的，
    真实玩家是首字母大写的名字。清理账号前**先备份 DB 再 diff**——
    上一轮就误删过 11 个角色（其中 2 个是测试号，873 个真人无损）。

## 12. 2026-10-22 第二轮：碰撞、模型一致性、移动可见性

### 12.1 移动后要刷新才看见（修）

根因：`move_object` 回包只有 `{id,x,z,rot}`，**没有 catalog/model**

## 19. 2026-10-22 第九轮：躺床穿模 / 别人坐躺时抽动

### 19.1 躺床偶发穿出床头

根因有两个：
1. 躺姿的偏移方向用的是**玩家自己的朝向**，床被旋转后方向就歪了；
2. `H.g.rotation.set(-1.45, yaw, 0)` 用默认 XYZ 欧拉顺序 —— Y 转 90°/180° 后
   “躺”的方向跟着歪 → 头穿出床外（所以是“有概率”）。

修法：
- 服务端 `sleep_state` 带上 **床的 rot**（`yaw`），并记到 `p.sleepYaw`；
- 客户端躺姿统一按床的朝向算，旋转顺序改 **YXZ**（先转向、再躺下），
  偏移 `SLEEP_OFF = 0.55`（脚在床尾一侧，头压枕头）。

测试 `tools/test_sleep_pose_e2e.py`：把床转到 0/90/180/270°，量躺姿包围盒在床本地坐标
的范围，四种朝向都落在 `X ±0.34 / Z ±0.98`（床板 1.60×2.05），不再穿出。

### 19.2 别人坐在椅子上 / 躺在床上一直抽动

**根因（很隐蔽）**：服务端 `world` 快照里的 `seat` 是**字符串**（`str(...)`，值如 `'obj334'`），
而客户端三处都写的是 `typeof w.seat === 'number'` → 永远得 -1。

于是远端玩家：
- 一直按**站姿**渲染（座位姿态从来没生效）；
- 位置一直走**网络插值**，而坐着的人每隔一包都被瞬移到椅子坐标
  → 插值来回追 → 看上去一直在抽动。

修法：
- `seat` 按字符串解析（`String(w.seat)`，`'-1'` 表示没坐）；
- `netUpdate` 里：**坐着或躺着时直接吸附服务端坐标**，不走插值，并摆出坐姿/躺姿
  （坐着：大腿抬平；躺着：用 `P.sleepYaw` 同样的公式）；
- `world` 快照新增 `syaw`（别人躺下时的朝向）；
- 顺带修了“远处队友坐着”那段同样按 number 判断的旧代码。

测试 `tools/test_remote_pose_e2e.py`：A 坐下后，观察者连续采样 8 帧
`posSpread=0.0000 yawSpread=0.0000 seat=obj334` —— 完全静止，不再抽动。


## 20. 2026-10-22 第十轮：抽动的真根因 + 三条交互规则

### 20.1 别人坐/躺一直抽动 —— 真根因在【广播】

上一轮只修了客户端读 `seat` 的类型，用户说"还是抽"，并且"自己坐下没问题"——
因为**客户端一直在上报位置，服务端无条件采纳**：

`_handle_intent` 的 `move` 分支末尾原来是

```python
p.x = _nx
p.z = _nz
```

无条件写。人坐下后服务端把坐标设成椅子位置，但客户端下一帧又把自己的本地坐标发上来
→ 服务端跟着改 → 广播里坐标在"椅子"和"客户端本地"之间来回跳
→ **别人看着你一直在抽动**（你自己看自己用的是本地状态，所以没事）。

修法：坐着（`seat != '-1'`）或睡着（`sleepHouse`）时**不采纳 move 的位置**，
只更新朝向。测试 `tools/test_remote_pose_e2e.py` 里让 A 坐下后**持续上报 move**：

```
5076: seat=obj334  x=-159.6        ← 坐标稳在椅子上
sit: posSpread=0.0000 yawSpread=0.0000
```

### 20.2 刷新后要保存坐/睡

- 服务端 `me` 包新增 `seat` / `sleep` / `syaw`（原来只有 hp/gold）；
- 服务端内存记一份 `last_pose[role_id]`（坐/睡时写，起身清除），
  重连 90 秒内自动恢复座位（不校验距离，因为是恢复不是新坐下）；
- 客户端另存一份在 `localStorage`（`UI.savePose/getPose`），
  连上后按 0.7/1.5/2.6 秒三次重试补发请求，双保险。

测试：`seatid before reload: 'obj527'  after reload: 'obj527'`。

### 20.3 三条交互规则

| 用户要求 | 修法 |
|---|---|
| 提示 3 秒就消失，得走开再靠近 | `showPrompt(id, text, sticky)`：**交互提示改成常驻**（状态类），只有一次性提示才 3 秒消失 |
| 床要贴着才能交互 | 睡觉判定 2.6m/6m → **1.4m**；放置房屋也改成"离它自己的床 1.4m"（不再整栋 6m） |
| 坐着/躺着点交互应是起身/起床 | `atkDown` 里把 `MY_SLEEP` / `MY_SEAT` 提到最前面（之前被"多交互弹窗"挡住了），并删掉后面重复的死分支 |

测试 `tools/test_interaction_rules_ui.py`：
提示 4 秒后仍是 block；坐着点按钮 `called=stand, picked=False`；床 2.2m→0、0.6m→1。

## 23. 2026-10-22 第十三轮：睡觉不再拉别人 / 进屋只淡化墙

### 23.1 点睡觉会把别人也拉过来

根因两头：
- 服务端 `sleep_state` **广播给所有玩家**；
- 客户端 `sleepApply(d)` 不判断这条消息是不是自己的，直接 `P.x/P.z = d.x/d.z`
  → 别人一睡觉，你也被瞬移到他的床上。

修法：
- 服务端只发给本人，并带上 `self=1`；
- 客户端 `sleepApply` 第一行 `if (!d.self) return;` 兜底。

测试 `tools/test_sleep_no_pull_e2e.py`：A 睡觉，B 的坐标 `moved: 0.000 m`。

### 23.2 进屋时连屋里的东西一起变透明

根因：`interiorTick` 是对**整栋建筑**的所有网格设 opacity，
而家具/柜台/地板都在建筑模型里 → 一起被淡化。

修法：`buildMesh` 把建筑拆成三个部分：
- `__roof`（名字含 roof/ridge）→ 进屋直接隐藏；
- `__walls`（名字含 wall/parapet/door_header/belt_band）→ 进屋淡化到 0.12；
- 其余（地板、家具、柜台、招牌…）→ **保持原样**。

★ 关键坑：这两个组必须打 `userData.noBatch = true`，
否则 `townBatchStatic` 会把组里的网格合批移走 → 组是空的 → 墙根本淡化不了
（`wallsKids: 0` 就是这么查出来的）。

测试 `tools/test_interior_fade_ui.py`：
`walls: {opacity: 0.12, transparent: true} / roofVisible: false / others: {opacity: 1}`。
