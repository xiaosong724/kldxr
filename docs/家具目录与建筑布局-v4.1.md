# 家具目录与建筑默认布局（v4.1）

> 目标：建筑内景里的家具不是装饰，而是**默认布局**——建筑放置时按布局生成真实物件，之后可单独移动/移除/再次放置。
> 状态：设计确认，开始落数据。

---

## 1. 核心规则

1. 家具 = 目录物件，有尺寸、价格、碰撞、功能；
2. 建筑 = 目录物件 + **默认布局清单**（`layout_json`）；
3. 建筑放置时，按布局在世界坐标生成家具物件；
4. 生成的家具**归建筑主人**，可移动、可移除；
5. 家具在建筑内是"默认摆放"，不是"长在墙上"；
6. 模型内景仍然渲染，用于**预览默认布局**；正式游戏由物件数据生成；
7. 建筑移动时，默认家具一起移动；单独移动家具不移动建筑。

---

## 2. 两层数据

### 2.1 目录（town_catalog）

建筑和家具都进同一张目录，用 `category` 区分：

```text
category: building | furniture | decor | function
```

新增字段：

```text
model_id      关联 TOWN_MODELS 的 key（建筑/家具模型）
model_version v1/v2...
layout_json   仅建筑：默认家具布局
place_mode    grid | free
```

### 2.2 布局（layout_json）

```json
{
  "floors": [
    {
      "y": 0,
      "items": [
        {"catalog":"bed_single","x":-2.15,"z":-2.65,"rot":0},
        {"catalog":"sofa_modern_2","x":2.55,"z":2.10,"rot":0},
        {"catalog":"chair_wood","x":1.0,"z":2.1,"rot":3.14}
      ]
    },
    {
      "y": 3.30,
      "items": [
        {"catalog":"bed_single","x":-1.0,"z":-1.4,"rot":0}
      ]
    }
  ]
}
```

- `x/z` 为建筑局部坐标；
- `rot` 弧度；
- `y` 为楼层高度（二层）；
- 生成时变成 `town_objects` 记录，带 `parent_building_id`。

## 4. 代码改造点

### 4.1 家具必须成组

现在：
- 床、沙发、冰箱已经是 Group；
- **椅子、咖啡机、厨房、卫生间洁具是散 mesh**。

必须先改造：每个家具一个 Group（或至少一个根节点），组上写：

```js
group.userData.furnitureId = 'chair_wood';
group.userData.catalogId   = 'chair_wood';
```

否则无法作为一个整体移动。

### 4.2 从内景改为"布局生成"

`buildTownInterior` 目前直接 `tmBox` 摆家具。改法：

- 保留内景渲染用于预览；
- 新增 `TOWN_LAYOUTS[modelId]`，定义每件家具的 catalog + x/z/rot/y；
- 建筑放置时服务端按 `layout_json` 生成物件；
- 预览页可以用同一份布局高亮显示"这些会变成可移动物件"。

### 4.3 碰撞

每件家具给一个 AABB：

```json
"collision": "[[-0.8,0,-0.4,0.8,1.0,0.4]]"
```

建筑外壳给整体碰撞，家具给局部碰撞。
