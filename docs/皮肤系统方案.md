## 一、"改高矮 / 改肢体长度"怎么自动适配

### 1.1 现在哪些是写死的

`hero()` 里全是魔法数字，所以一改骨架就会错位：

| 位置 | 现在的写死值 | 谁依赖它 |
|---|---|---|
| 手臂枢轴 | `(±0.66, 1.82)` | 挥刀动作 |
| 剑的挂点 | `handPivot.y = -0.95` | **手握位置**（手臂变长 → 剑浮空 ✗）|
| 头 | `y 2.46`，尺寸 `1.10×1.02` | 眼睛/嘴/头发 |
| 腿枢轴 | `(±0.26, 0.86)`，长 `0.92` | 脚要刚好落地 |
| 靴子 | `y -1.0`（贴腿末端）| 走路时会不会悬空 |
| 影子 | 半径 `0.62` | 脚底圆影 |
| **头顶名字/血条** | `(px, 3.2, pz)` 硬编码 ✗ | 皮肤变高 → **名字陷进头里** ✓ |
| 相机跟随/攻击特效高度 | 写死 | 高个子看着要抬头 |

### 1.2 改法：把"骨架"变成一张参数表，其它全部**算出来**

```js
// 每个皮肤一份（不填就走默认值 = 现在这套）
var SKEL_DEF = { s: 1.0, hip: 0.86, legLen: 0.92, bootH: 0.30,
                 torsoH: 0.98, torsoW: 1.02, armLen: 0.92, armW: 0.30,
                 armX: 0.66, armY: 1.82, headW: 1.10, headH: 1.02,
                 headY: 2.46, hairH: 0.34 };
```

所有"依赖位置"改成**从参数算**（这是自动适配的核心）：

| 需要的位置 | 公式 |
|---|---|
| 剑的挂点 | `handY = -(armLen - 0.02)`（手在手臂末端）|
| 手臂末端（手方块） | `armLen` 处 |
| 靴子 | `legLen - bootH/2` 处（保证**脚落地**）|
| 头顶高度 | `headTop = headY + headH/2 + hairH` |
| **名字/血条** | `plateY = headTop * s * HERO_SCALE + 0.12` |
| 影子半径 | `hipW * 0.62` |
| 相机跟随点 | `(torsoY + torsoH*0.5) * s` |
| 受击/暴击数字弹出高度 | `plateY * 0.75` |

### 1.3 加一条硬校验（自动测试，不靠肉眼）

`tools/test_skin_rig.js` 对**每个皮肤**跑一遍：

| 检查 | 判定 |
|---|---|
| 脚底贴地 | `|hip - legLen - bootH| < 0.02` |
| 手握对齐 | 剑柄与手方块中心偏差 `< 0.02` 米 |
| 名字在头顶之上 | `plateY > headTop * s + 0.05` |
| 影子盖住双脚 | `shadowR` 在脚宽 ~ 髋宽之间 |
| 缩放范围内 | `0.90 ≤ s ≤ 1.10`（防"视觉欺骗"：手更长看起来更远）|

**结论**：只要坚持"同一套枢轴语义 + 参数化 + 上面这条校验"，**改高矮、改肢体长度、加配件全都能自动适配** ✓
唯一硬限制：**别忘了手/脚/头都是"从参数算出来的"**，一旦有人再写死一个 3.2，校验就会红 ✓

> ⚠️ 服务端判定**完全不受影响**：攻击距离用的是常量（单手剑 2.4 米），不看模型尺寸 ✓
> 所以皮肤不会改变战力，也不会出现"高个子打得更远"✓

## 二、皮肤跟账号 / 跟角色 —— 其实现在等价，但要说清楚

现在一个账号只能建**一个角色**，所以"账号级皮肤"和"角色级皮肤"结果完全一样 ✓
差别只会在**以后一个账号多个角色**时出现：

| 存法 | 多角色时表现 |
|---|---|
| 存**角色**（`roles.skin`）| 每个角色各自一套外观、各自解锁（推荐）|
| 存**账号**（`accounts.skin`）| 换角色外观不变、解锁共享 |

**我建议存角色**（`roles.skin` + 解锁表按 role_id）：
- 以后要多角色时天然支持 ✓
- 现在只是"多一层角色 id"，不影响任何逻辑 ✓

## 十一、切换皮肤会不会出问题（逐条过一遍）

### 11.1 核心设计：**骨架永不动，只换"外观层"**

每个角色 = `骨架（limbs/枢轴，只建一次）` + `外观层（appearance group）`

```
H.g
 ├─ skeleton: armL/armR/legL/legR + sw/swL   ← 永远不动，动画都在转这些
 └─ parts   : 头/头发/眼睛/衣/腰带/配件       ← 切换皮肤只换这一层
```

- 6 套 `parts` **在进世界时一次性建好**（约 6×22 = 132 个方块，几何/材质都走缓存）
- 切换 = `parts[i].visible = true`，其它 `false` ✓ **零重建、零 dispose、零卡顿**
- 远程玩家的 `parts` = 从同一份模板 `clone()`（**共享 geometry**，只复制节点）✓

**为什么这样最安全**：动画、死亡姿态、武器挂点、插值全挂在骨架或全局计时器上，
换外观层**碰不到它们** ✓

### 11.2 逐条风险表

| 场景 | 会不会出问题 | 原因 / 处理 |
|---|---|---|
| **攻击动画进行中**切换 | ❌ 不会 | 挥刀转的是 `armR`，在骨架层；`atkT` 在全局 ✓ |
| **死亡躺平**时切换 | ❌ 不会 | `H.g.rotation.x = -1.45` 每帧重设，在外层 group ✓ |
| 跳跃 / 被击退 / 传送旋转 | ❌ 不会 | 同上，动的是 `H.g` 不是外观 ✓ |
| **手上武器**（含耐久/损坏）| ❌ 不会 | `sw/swL` 是骨架的一部分，`fillHeldWeapon` 没被调用 ✓ |
| 头顶名字 / 血条高度 | ⚠️ 要更新 | 按新皮肤 `headTop` 重算 `plateY`（已参数化）|
| 脚底影子半径 | ⚠️ 要更新 | `shadowR = hipW × 0.62`，换皮肤时改一次 |
| 相机跟随点（胸口高度）| ⚠️ 要更新 | `chestY × s`，换皮肤时改一次 |
| 受击/暴击数字弹出高度 | ⚠️ 要更新 | 走 `plateY × 0.75` |
| 服务端伤害/命中/距离 | ❌ 不会 | 服务器用常量，不看模型 ✓ |
| 别人看到你换皮肤 | ⚠️ 要同步 | 快照 `sk` 变化 → 对方切 `parts` ✓ |
| 切换失败（没解锁 / 未知 key）| ✅ 已处理 | 服务端拒绝 → 客户端保持原皮肤 + 提示 |
| 重登 / 刷新 | ✅ 已处理 | 从 `roles.skin` 恢复 |
| 多人同屏都在切 | ❌ 不会 | 每人各切自己的 `parts`，互不影响 |

### 11.3 唯一会"真出问题"的情况：**皮肤想换骨架**

如果某个皮肤的 `hip / legLen / armLen` 和默认不一样 ✗
→ 就**不能只切外观层**，必须重建骨架 ✓

**我的建议：结构上就不允许** —— 皮肤表只开放三个字段：

```js
SKIN[key] = {
  pal:  { shirt: 0x8b1a1a, pants: 0x222222, ... },  // 颜色
  extra:[ {part:'head', w:.9,h:.2,d:.9, y:1.55, c:0x111} ], // 配件
  s:    1.02                                        // 整体缩放（0.90~1.10）
}
```

- `hip / legLen / armLen / headY` **不在皮肤表里** → 皮肤改不了骨架 ✓
- 想"更高"就用 `s`（整体缩放，武器/配件/名字/影子一起缩）✓
- 校验里加一条：`s ∈ [0.90, 1.10]`，超了直接报错 ✓

### 11.4 如果以后你确实想给某个皮肤换骨架（大块头 / 侏儒）

那需要一条单独的"重建"路径，代价与处理：

| 步骤 | 说明 |
|---|---|
| 保存现场 | 位置 / 朝向 / 死亡姿态 / 武器 look+tier+耐久 / 攻击与走路计时器 / 传送旋转进度 |
| 重建 | `hero(newSkinnedDef)` 造新骨架 |
| 恢复 | 按上面那 6 项还原（少一项就"切完站着不动/武器消失/躺着的站起来"）|
| 限制 | **禁止在攻击/死亡/传送中切**（有 1 帧姿态跳变）|
| 同步 | 快照要多带"骨架版本"，不然别人看到的是旧身高 |

★ 结论：**能做，但没必要**。你要的"高矮差异"，用 `s`（0.90~1.10）+ 配件就能做出明显区别 ✓

### 11.5 切换的完整流程

```
玩家点「使 用」
  → 客户端发 setskin{key}
  → 服务器校验：这个 key 存在？这个角色解锁了吗？
       ├─ 不通过 → 回 error → 客户端保持原皮肤 + toast
       └─ 通过   → roles.skin = key（post_save 落库）
                  → 回包 skin{key}
                  → 广播（快照 sk 生效）
  → 客户端收到 skin 包：
       ① 切 parts 可见性
       ② 更新 plateY / shadowR / chestY
       ③ 皮肤页把「使用中」标记挪过去
  → 别人：快照里 sk 变了 → 切他那份 parts
```

★ **不做"乐观更新"**（先切再等服务器）：因为切错了要回滚，视觉会闪两下 ✓
　 服务器回包在局域网/云上都是几十毫秒，感觉不出来 ✓

## 十七、皮肤独有权（金币买断竞价）· 方案（round482）

> 用户："皮肤独有权，玩家可以有对应皮肤后，可以选择给对应皮肤进行金币买断，
> 出价最高的三个人才能使用，可以看到出价前三的人，
> 并且如果第一名出价高于第二30%后，就只能第一一个人用了。
> 这个出价是可以累计的，但是不能退款。皮肤如果无人出价，大家都可以用，或者出价一样"

### 17.1 一句话规则

**每个皮肤一个竞价榜**：解锁了这个皮肤的人才能出价（金币，**扣了不退**，可累计），
按累计金额排名：

| 情况 | 谁可以用这个皮肤 |
|---|---|
| 没人出价 | **所有解锁了它的人**都能用 |
| 有人出价，第一名 < 第二名 × 1.3 | **前三名**都能用（并列同额的都算） |
| 第一名 ≥ 第二名 × 1.3 | **只有第一名**能用（独占） |

★ 榜单公开：皮肤页能看到**前三名的名字和累计出价** ✓
★ 出价**可以一直加**（累计），但**永不退款** ✓
★ "并列"：金额一样的人算同一档——并列第 3 就一起进前三；并列第 1 时**不算独占**（没有"严格第一"）✓

### 17.2 出价规则（我建议的数值，等你确认）

| 项 | 建议值 | 说明 |
|---|---|---|
| 起拍价（第一次出价）| **5,000 金币** | 防止 1 金币占位 |
| 每次加价幅度 | **≥ 1,000 金币 或 当前累计的 10%（取大）** | 防止"每次加 1 块"恶心人 |
| 单次上限 | 10 亿（= 现有金币上限内）| 和 `_gain_gold` 一致 |
| 扣钱时机 | **出价成功立刻扣** | 走 `_gain_gold(-n)`，扣不动就拒绝 |
| 退款 | **永不退** | 出价前二次确认，写明"不退" |
| 独占阈值 | 第一 ≥ 第二 × **1.3** | 用户定的 30% |
| 榜单展示 | 前 3 + 自己（第 4 名以后只显示自己名次）| — |
| 是否永久 | 永久，直到被更高价超过 | 不做赛季重置（可留开关）|

### 17.3 会出问题的边界（都要处理）

| 场景 | 处理 |
|---|---|
| 正在用这个皮肤，被被人挤出前三 | **立刻降级**：自动换回"上一个可用的皮肤"或默认皮肤，弹提示 |
| 正在用，被第一名独占挤掉 | 同上 |
| 出价时金币不够 | 拒绝，提示还差多少 |
| 出价低于门槛 | 拒绝，提示最低要出多少 |
| 自己已经是第一名还想加价 | 允许（累计更高，独占更稳）|
| 并列第一 | 不算独占（两人都用）|
| 皮肤只有 1~2 个人出价 | 前三名 = 实际出价人数（都可用）|
| 玩家解锁了皮肤但没出价，而榜上有 3 个人 | 该玩家**不能用**（前三才可以用）|
| 玩家解锁了皮肤，榜上没人 | 能用 ✓ |
| 重复出价累计到很高后掉出前三 | 钱不退，可用权没了（**这是本方案最容易挨骂的点，必须出价前确认**）|

### 17.4 数据结构

| 表 / 字段 | 内容 |
|---|---|
| `roles.skin` | 当前使用的皮肤（已有）|
| `skin_unlocks(role_id, key, at)` | 解锁表（已有）|
| **`skin_bids(role_id, key, total, times, at)`** | 竞价累计（主键 role_id+key）|
| 内存 `world.skin_rank[key]` | 按 total 降序的榜单缓存（启动时从库加载，出价时更新）|

### 17.5 协议

| 消息 | 方向 | 内容 |
|---|---|---|
| `skinbid{key, amount}` | C→S | 出价（amount = **这次加多少**，不是总额）|
| `skinpage` | C→S | 打开皮肤页时拉一份完整状态 |
| `skinrank{items:[{key, top:[{name,total,me}], mine, canUse, exclusive, need}]}` | S→C | 榜单 + 我的状态 + 能不能用 |
| `notice` | S→C | "加价成功" / "被挤出前三" / "金币不足" |

★ 服务端是唯一裁决者：客户端只显示，不算排名 ✗

> 用户："裙子看起来好像和腰看起来不协调，腰细，把裙子上面的收口小点"
