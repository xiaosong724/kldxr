# 咖啡店点单与传菜方案（后续实现）

> 状态：方案补充，未实现
> 关联：`城镇方案 v4` 的商店/家具功能、权限、放置物

## 1. 两种购买方式

### 直接购买

- 玩家站在柜台/收银台前点单；
- 付款后商品直接进背包；
- 不占桌子、不生成桌上物品；
- 适合外带。

### 坐下点单

- 玩家坐到咖啡店的椅子上；
- 以“这张桌子”为单位点单；
- 付款后生成一张**桌上订单**；
- 传菜员从出餐口走到桌边，放下咖啡；
- 桌上出现咖啡杯模型；
- 玩家可以继续点，最多不超过这张桌子的椅子数；
- 点过的杯子会占桌位/杯位，喝掉或收走后释放。

## 2. 桌子与座位

每张桌子配置：

```text
table_id
chairs: [seat_id...]
max_cups: = chairs.length
current_cups: [...]
linked_order: ...
```

- 一张桌子有几张椅子，就最多同时摆几杯；
- 桌子可以是一人桌/两人桌/四人桌；
- 椅子必须属于这张桌子；
- 玩家坐的椅子决定使用哪张桌子；
- 多张桌子互不影响。

## 3. 订单状态

```text
pending   已付款，等待传菜
cooking   制作中
carrying  传菜员取餐，正在走
served    已放到桌上
drunk     已饮用/收走
```

服务端保存：

- 订单所属小镇/商店/桌子；
- 点单人；
- 商品与杯数；
- 当前状态；
- 传菜员 NPC id；
- 到期/取消时间。

## 4. 传菜员

- 每家有堂食的店有 1 个传菜员岗位；
- 出餐口 → 桌边有路径点；
- 传菜员拿托盘走到桌边；
- 到桌边后播放放杯动作；
- 桌上生成对应杯子模型；
- 传菜员返回出餐口；
- 玩家坐下点单后，订单进入队列；
- 没有传菜员/岗位无人时，订单提示“暂时没有传菜员”，不扣款或延迟。

## 5. 桌上杯子

- 每个杯位对应一个椅子/位置；
- 模型使用咖啡杯/饮料杯/餐盘；
- 杯子可点击：
  - 喝掉；
  - 收走；
  - 查看是什么。
- 喝掉后：
  - 应用食物/饮料效果；
  - 释放杯位；
  - 可以继续点。

## 6. 与现有系统关系

- 现有“点单直接进背包”要改成：
  - 柜台直接买 → 进背包；
  - 坐下点单 → 桌上订单；
- 现有 `order` 协议需要增加 `table_id`、`seat_id`、`cups`；
- 服务端新增 `shop_tables`/`table_orders` 数据；
- 传菜员 NPC 需要路径/动作；
- 桌子/椅子来自可放置物目录，有碰撞和桌位配置；
- 权限：`trade` 可点单；店主/有 `price` 权限可改价。

## 7. 需要新增的数据

```text
shop_tables(id, town_id, shop_id, x, z, chairs_json, max_cups)
table_orders(id, table_id, player_id, shop_id, items_json, state, waiter_id, created_at)
table_cups(id, table_id, order_id, item, slot, state)
waiter_tasks(id, shop_id, order_id, path_json, state)
```

## 8. 优先级

1. 桌子/椅子归属；
2. 坐下点单；
3. 桌上杯位；
4. 传菜员路径和放杯动画；
5. 多杯/多桌；
6. 服务端存档与重启恢复。
