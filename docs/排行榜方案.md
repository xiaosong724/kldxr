## 3. 数据模型（迁移 **v10**，只加列/表/索引，幂等）

```sql
-- ① 每人一行计数（以后成就也复用这张表）
CREATE TABLE IF NOT EXISTS role_stats (
    role_id    INTEGER PRIMARY KEY,
    kills      INTEGER NOT NULL DEFAULT 0,   -- 击杀僵尸（PvE）
    deaths     INTEGER NOT NULL DEFAULT 0,   -- 死亡次数（留给成就，顺手记）
    pvp_kills  INTEGER NOT NULL DEFAULT 0,   -- 击杀玩家（PvP，防刷窗口内只算一次）
    play_sec   INTEGER NOT NULL DEFAULT 0,   -- 在线时长（秒）
    updated_at INTEGER NOT NULL DEFAULT 0
);

-- ② 称号：选哪个榜挂头上（'' = 不显示）
ALTER TABLE roles ADD COLUMN title_board TEXT NOT NULL DEFAULT '';

-- ③ 排序索引
CREATE INDEX IF NOT EXISTS ix_stats_kills ON role_stats(kills DESC);
CREATE INDEX IF NOT EXISTS ix_stats_pvp   ON role_stats(pvp_kills DESC, updated_at);
CREATE INDEX IF NOT EXISTS ix_stats_time  ON role_stats(play_sec DESC);
CREATE INDEX IF NOT EXISTS ix_roles_level ON roles(level DESC, exp DESC);
CREATE INDEX IF NOT EXISTS ix_roles_gold  ON roles(gold DESC);
CREATE INDEX IF NOT EXISTS ix_roles_mq    ON roles(mq DESC);
```

**历史数据**：境界/财富/魔气立刻有；**屠戮/PvP/在线从 0 开始**（以前没记过，无法回填）——

## 4. 三个计数怎么记（线程纪律）

| 计数 | 挂在哪 | 频率 | 落库 |
|---|---|---|---|
| `kills`（僵尸） | `_mob_died(p, m)` 里 `p.st_kills += 1`（已有"每只怪只结算一次"保护） | 每次击杀 | 30 秒 / 下线，走 `post_save` |
| `pvp_kills`（玩家） | `_pvp_killed(killer, victim)` 里 → **只在防刷判定通过时 +1**（同一对手 10 分钟只算一次，和魔气同一把锁） | 每次 PvP 击杀 | 同上 |
| `play_sec`（在线） | tick 里 `p.st_play += dt`，攒够 1 秒才进整数 | 每秒 | 同上 |

```
tick 线程：只改内存（纳秒级）✓ 绝不写盘 ✓
存档线程：INSERT INTO role_stats(...) ON CONFLICT(role_id) DO UPDATE ...
```

★ 为什么 PvP 击杀跟魔气共用防刷锁：不然开小号互刷就能刷榜 ✓
★ 僵尸击杀不用防刷：单刷僵尸慢，榜的含金量靠时间 ✓

## 5. 称号（头顶显示）—— 这次的重点

### 5.1 数据流

```
HTTP 线程（每 60 秒，或有人改称号时立刻算）
   └─ 把 5 个榜各查一次 → 建「role_id → rank」映射（算前 100 名 + 当前玩家自己）
      → 发布到 world.rank_map（普通 dict，只读快照 ✓ 和 admin_stat 一个路子）

tick 线程（每帧）
   └─ 给每个在线玩家算称号文本（纯查表，微秒级 ✓）
      rank = rank_map[role_id][该玩家选的榜]
      存在且 rank ≤ 100 → '国服{榜名}top{rank}'
      → 写进快照（others / me）两个字段：
          tt = 称号文本（'' = 不显示）
          tm = 名次 1/2/3（画金/银/铜牌，其它 0）

客户端
   └─ 名牌最上面一行渲染称号（前三名前面加奖牌）
```

### 5.2 显示规则

```
        ┌─────────────────────────┐
        │ 金 国服在线top1          │  ← ① 称号（最顶上，可关）
        │ 魔气图标 9749            │  ← ② 魔气（原来就有，位置不变）
        │ ★ 半个六道  炼气 32 层    │  ← ③ 名字（原来就有）
        │ ▓▓▓▓▓▓▓▓░░░ 123/130      │  ← ④ 血条
        └─────────────────────────┘
```

| 规则 | 值 |
|---|---|
| 位置 | **名牌最上面**（魔气那行之上）✓ 不和名字/魔气挤 ✓ |
| 名次上限 | **只显示前 100 名**（>100 不挂称号，「top100」是格式上限） |
| 前三名 | 称号前加奖牌：金 / 银 / 铜（emoji 奖牌，颜色也变） |
| 别人看得见 | ✅ 快照带 `tt`/`tm`，别人和**自己**的名牌都显示 |
| 可关 | ✅ 设置里勾掉 → `title_board=''` → 1 秒内自己+别人都消失 |
| 换榜 | ✅ 选另一个榜，1 秒内换掉 |
| 数据来源 | 名次由**服务端**算 ✓ 客户端不能自己写称号 ✓ |

### 5.3 存储

`roles.title_board`：`''`（关）/ `level` / `gold` / `kills` / `mq` / `time`
→ 重启服务器后仍然记着 ✓（和"背包上锁"一样，不能丢）

## 7. 接口 / 协议

### 7.1 HTTP（只读）

```
GET /api/rank?board=level|gold|kills|mq|time&page=1&size=10
```
```jsonc
{ "ok": true, "board": "mq",
  "rows": [ { "r": 1, "name": "半个六道", "lv": 32, "v": 12,
              "sub": "魔气 9749", "on": true, "medal": 1 } ],
  "me": { "r": 137, "v": 0, "in100": false },   // 名次总会给你
  "total": 185, "topN": 100, "pages": 10, "cacheAge": 12, "ts": 1792285000000 }
```
- **只返回前 100 名**；每页默认 **10** 个（`page` 1~10，`size` ≤ 20 防刷）
- `me` **总是返回**；`in100=false` = 没进前 100、头顶不显示称号
- 每榜 60 秒缓存；`?force=1` 只给管理员
- 测试号（`config.test_name_keys`）不上榜
- 只给：名字 / 等级 / 该榜数值 / 在线状态 —— **不给金币来源、背包、坐标**

### 7.2 WS（写，只改自己）

```
C2S  ranktitle { board: "level|gold|kills|mq|time|''" }   → 设置头顶称号（'' = 关）
S2C  ranktitleok { board, text }                          → 回执（客户端显示当前称号）
```
- 进 `server/protocol.py` 的 C2S 白名单 ✓（上次 `baglock` 就漏在这儿报"未知消息类型"）
- 网络线程校验 → 写库（`UPDATE roles SET title_board=?`）→ 入 `world.inbox` 让 tick 立刻刷新一次快照

### 7.3 快照字段（新增 2 个）

```
others[] / me 里追加：tt = 称号文本（'' = 不显示）、tm = 1/2/3 名次（0 = 没牌）
```
★ `tools/check_field_map.py` 是"两边字段一致"的闸门 → 加字段必须两边同时改 ✓

   只给管理员 token 用（测试/排查时强刷，不然要等 60 秒缓存）。普通玩家传了会 403。
