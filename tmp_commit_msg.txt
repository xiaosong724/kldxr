cloud sync: deploy the exchange work and migrate the live db v3 -> v7

The cloud was far behind: schema v3 against the local v7, no market.py, no value.py, and
no exchange in the served page. It also holds real players - 122 roles, ten of them with
progress (fangou 68, xlllcg 54) - so nothing here could be done casually.

The risky part was the schema, which had to jump four versions on a live database. I
pulled a copy first and ran the migration locally against the real data: 122 roles and
3004 items in, the same out, three new tables added, nothing dropped. The local code
then loaded that migrated database and read every player's bag without a single
unparseable item. Only after that did I touch the server.

Deployment: backed up the cloud database and code to a timestamped directory, stopped
the service, uploaded an explicit list of eleven files with an md5 check on each,
started the service (which runs the migration), and verified from outside - the health
endpoint, the new panes and buttons present in the served HTML, the new logic present in
the served web.js, both ports reachable, and a fresh account on the public address
receiving a weapon and reading it back with its durability.

Two of my own mistakes worth recording: the migration step built a python one-liner
inside an ssh command, which tripped both python's % formatting and shell quoting and
crashed with the service already stopped (finished by hand, and the script now uploads a
check file instead of quoting anything); and I used an eleven character account name
when the limit is ten.
